# 接口设计文档

**项目：** 在线购物系统（单商家 · 挑战C升级版）
**角色：** 成员2 —— 后端开发岗
**版本：** V3.0
**日期：** 2026-11-24
**框架：** Spring Boot 2.7.18（Java 8）+ springdoc-openapi 1.6.15（OpenAPI 3.0）
**在线文档：** `http://127.0.0.1:8000/docs`（Swagger UI）；`http://127.0.0.1:8000/redoc` 自动跳转至 `/docs`

> **本版变更**：V3.0 依据《需求规格说明书-挑战C升级版》重写**买家端**接口，在挑战B 的收藏 / 购物车 / 多选下单基础上，补齐挑战C 的线上支付（回调验签、失败重试、24 小时超时取消）、客户取消与退款、收货地址、物流查询、售后服务。
>
> **卖家端接口本轮不升级**：第 6 章沿用 V2.1 原文，其中仍为「意向 / 排队 / 交易」模型，与第 5 章的新订单模型并存，仅作为现状记录；挑战C 的商家订单推进、发货、售后处理属于后续版本内容。

## 1. 通用约定

| 项目 | 约定 |
|---|---|
| Base URL | `http://127.0.0.1:8000` |
| 编码 | 请求/响应体统一 UTF-8，`Content-Type: application/json` |
| 时间格式 | `YYYY-MM-DD HH:MM:SS`（本地时间字符串） |
| 金额 | 出参 `price` / `total` / `amount` / `subtotal` 为元（保留 2 位小数，数值类型），同时给出对应的 `*_cents`（整数分）；入参 `price` 为元，必须 > 0 且最多两位小数 |
| 鉴权 | `Authorization: Bearer <token>`。角色为 `seller` / `customer`；公开浏览与搜索免鉴权；客户接口需客户令牌，跨角色调用返回 401 |
| 令牌 | 无状态 HMAC-SHA256 令牌，载荷含角色与主体 ID，形如 `role.subjectId.expiresAt.signature` |
| 游客标识 | `X-Guest-Id`：8~64 位字母、数字、下划线或短横线，仅 `/api/guest/**` 使用；登录时携带该头，服务端会把游客的收藏/购物车并入账号 |
| 分页 | 查询参数 `page`（≥1，默认 1）、`page_size`（1~100，默认 10）；超范围返回 422 |
| 密码规则 | 买家与卖家统一：去除首尾空白后 **8~128 位**，且大写字母、小写字母、数字、特殊字符四类中**至少包含 3 类**；登录不校验强度，仅校验账号与密码是否匹配 |
| 联系电话 | 支持 11 位手机号、带区号座机（`010-12345678`）、7~8 位本地座机；允许 `+86` 前缀、空格、短横线、中英文括号。保存前归一化为纯数字并去掉 `+86` |
| 数量上限 | 收藏 ≤ 200 件；购物车 ≤ 50 条；单条数量 1~99 件；单次下单 ≤ 50 件；售后图片 ≤ 9 张 |
| 事务与一致性 | SQLite WAL + `BEGIN IMMEDIATE` 单写事务；下单占用、取消回补、完成核销均在同一事务内完成；支付回调按支付单幂等 |
| 错误格式 | 统一 `{"error": {"code": "...", "message": "..."}}`，参数校验错误额外带 `details` |

### 1.1 错误码

| HTTP | code | 含义 |
|---|---|---|
| 400 | `BUSINESS_ERROR` | 通用业务错误 |
| 400 | `INVALID_IMAGE_FORMAT` | 商品图片格式不是 JPG / PNG |
| 400 | `IMAGE_TOO_LARGE` | 图片超过 5MB |
| 400 | `INVALID_MEDIA_FORMAT` | 富媒体文件格式不支持 |
| 400 | `MEDIA_TOO_LARGE` | 富媒体文件超过大小限制 |
| 400 | `EMPTY_FILE` | 上传文件为空 |
| 401 | `UNAUTHORIZED` | 未登录 / 令牌无效或过期 / 角色不符 / 旧密码错误 / 支付回调验签失败 |
| 404 | `NOT_FOUND` | 资源不存在（商品、类别、订单、订单项、收货地址、支付记录、物流、售后） |
| 409 | `CONFLICT` | 状态冲突（重复注册、重复收藏、超出上限、库存不足、订单状态不允许当前操作、尚未发货等） |
| 422 | `VALIDATION_ERROR` | 请求参数校验失败（如密码强度不足、数量越界、图片格式不符、缺少游客标识） |
| 500 | `INTERNAL_ERROR` | 服务器内部错误 |

**错误响应示例**

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "单条数量不能超过 99 件",
    "details": [
      { "loc": ["body", "quantity"], "msg": "单条数量不能超过 99 件", "type": "value_error" }
    ]
  }
}
```

### 1.2 状态取值

| 类别 | 取值 |
|---|---|
| 商品状态 | `ON_SALE`（在售）、`FROZEN`（冻结）、`SOLD_OUT`（售罄下架）、`OFF_SHELF`（手动下架） |
| 订单状态 | `PENDING_PAYMENT`（待支付）、`PAID`（已支付）、`SELLER_CONFIRMED`（商家确认）、`STOCK_READY`（备货完成）、`SHIPPING`（开始发货）、`COMPLETED`（交易完成）、`CANCELLED`（已取消） |
| 订单支付汇总 | `UNPAID`（未支付）、`PAID`（已支付）、`REFUNDED`（已退款） |
| 支付状态 | `SUCCESS`（支付成功）、`FAILED`（支付失败） |
| 支付方式 | `BANK_CARD`（银行卡）、`CREDIT_CARD`（信用卡）、`ALIPAY`（支付宝）、`WECHAT`（微信支付） |
| 退款状态 | `SUCCESS`（退款成功） |
| 物流状态 | `SHIPPED`（已发货）、`IN_TRANSIT`（运输中）、`DELIVERING`（派送中）、`SIGNED`（已签收）；未发货时订单侧为 `NOT_SHIPPED` |
| 售后状态 | `PENDING`（待处理）、`NEGOTIATING`（协商中）、`RESOLVED`（已解决）、`REJECTED`（已拒绝） |
| 库存占用（内部） | `ACTIVE`（占用中）、`RELEASED`（已回补）、`CONSUMED`（已核销） |
| 意向状态（第 6 章沿用） | `QUEUED`、`REQUEUED`、`IN_TRANSACTION`、`SUCCESS`、`FAILED`、`VOIDED`、`SOLD_OUT` |

- 订单状态单向推进：`PENDING_PAYMENT → PAID → SELLER_CONFIRMED → STOCK_READY → SHIPPING → COMPLETED`，`CANCELLED` 为终态；客户只能在 `SHIPPING` 之前取消。
- 订单对象同时给出三个可直接驱动前端按钮的布尔字段：`can_pay`（仅待支付）、`can_cancel`（待支付 / 已支付 / 商家确认 / 备货完成）、`can_after_sale`（仅交易完成）。
- 商品对外的 `stock` 为**可售数量**（原始库存 − 活跃占用），并额外给出 `available_stock` 便于对照；公开列表仍包含 `ON_SALE` 与 `FROZEN`。
- 客户下单即占用库存（`ACTIVE`），可售归零时商品自动转 `SOLD_OUT`；订单取消释放占用（`RELEASED`）并可售恢复，商品自动回到 `ON_SALE`。

### 1.3 相较 V2.1 的接口变化

| 类型 | 接口 | 说明 |
|---|---|---|
| 删除 | `POST /api/customer/intents` | 意向（排队）模型下线，改为收藏 / 购物车 / 订单 |
| 删除 | `GET /api/customer/intents`、`GET /api/customer/intents/{intent_id}` | 同上 |
| 语义变更 | `GET /api/customer/orders` | 由「意向记录」改为「订单列表」，支持 `status` 筛选并返回完整订单对象 |
| 修改 | `GET /api/products`、`GET /api/products/{product_id}` | `stock` 改为可售数量，新增 `available_stock`；详情移除 `queue_count` |
| 新增 | 收藏 3 个、购物车 5 个、下单 1 个、订单详情/取消/支付/物流 4 个、地址 5 个、售后 3 个 | 见第 5 章 |
| 新增 | 游客预选 9 个（`/api/guest/**`） | 未登录临时收藏 / 加购，登录后合并 |
| 新增 | `POST /api/payments/callback` | 模拟支付网关回调（验签 + 幂等） |
| 未变 | 第 6 章卖家接口、第 7 章文件接口 | 本轮不升级 |

## 3. 公共数据结构

### 3.1 商品对象 product

```json
{
  "id": "8f1c2a7e4b6d4c0e9a3f5d2b1c8e7f60",
  "name": "手工陶瓷杯",
  "description": "<p>手作限量</p><img src=\"/uploads/6d2f.png\">",
  "price": 99.9,
  "price_cents": 9990,
  "stock": 2,
  "available_stock": 2,
  "status": "ON_SALE",
  "status_label": "在售",
  "category_id": "c2b7...",
  "category_name": "杯子",
  "parent_category_id": "a1d9...",
  "parent_category_name": "厨房用品",
  "published_at": "2026-10-22 10:00:00",
  "created_at": "2026-10-22 10:00:00",
  "updated_at": "2026-10-22 10:05:00",
  "images": [
    { "id": "img01", "url": "/uploads/ab12.jpg", "sort_order": 1 },
    { "id": "img02", "url": "/uploads/cd34.png", "sort_order": 2 }
  ],
  "primary_image": "/uploads/ab12.jpg",
  "image_count": 2
}
```

- 买家侧 `stock` 与 `available_stock` 均为**可售数量**（原始库存 − 活跃占用）；卖家侧（第 6 章）仍返回原始库存。
- `images` 按 `sort_order` 升序，第 1 张即主图；无图时 `primary_image` 为 `null`、`image_count` 为 0。
- `description` 为富文本 HTML，内嵌资源均为 `/uploads/...` 本地上传地址。

### 3.2 收藏项 favorite

```json
{
  "id": "f3a1...",
  "product_id": "8f1c...",
  "created_at": "2026-10-22 10:05:00",
  "product": {
    "id": "8f1c...", "name": "手工陶瓷杯", "price": 99.9, "price_cents": 9990,
    "stock": 2, "available_stock": 2, "status": "ON_SALE", "status_label": "在售",
    "category_id": "c2b7...", "primary_image": "/uploads/ab12.jpg",
    "available": true, "unavailable_reason": null
  },
  "available": true,
  "unavailable_reason": null
}
```

- `available` = 商品在售且可售数量 > 0；`unavailable_reason` 取值 `已下架` / `无货` / `交易中`，商品被删除时为 `已下架` 且 `status_label` 为 `已删除`。

### 3.3 购物车对象 cart

```json
{
  "items": [
    {
      "id": "c1b2...",
      "product_id": "8f1c...",
      "quantity": 2,
      "price": 99.9,
      "price_cents": 9990,
      "subtotal": 199.8,
      "subtotal_cents": 19980,
      "created_at": "2026-10-22 10:05:00",
      "updated_at": "2026-10-22 10:06:00",
      "product": { "id": "8f1c...", "name": "手工陶瓷杯", "primary_image": "/uploads/ab12.jpg", "...": "..." },
      "available": true,
      "unavailable_reason": null
    }
  ],
  "item_count": 1,
  "total_quantity": 2,
  "total": 199.8,
  "total_cents": 19980
}
```

- `item_count` 为条目数，`total_quantity` 为数量合计，`total` 为按当前单价计算的金额合计。
- 收藏与购物车**均不占用库存**，可售数量只在提交订单时扣减。

```json
  "after_sale_count": 0
}
```

- 订单项的商品名称、单价、小计为**下单时快照**，不随商品改价而变化。
- `address` 为下单时固化的收货地址快照，不随地址簿后续修改而变化。
- `payment` / `refund` / `shipment` 为最近一条记录或 `null`；`payment_status` 为 `REFUNDED` 时表示已生成退款。
- `cancel_by` 取值 `CUSTOMER`（客户主动取消）或 `SYSTEM`（待支付超时）。

## 5. 客户接口

> 除注册、登录外均需 `Authorization: Bearer <客户令牌>`；令牌角色不为 `customer` 时返回 401。

### 5.1 POST /api/customer/register —— 客户注册

**请求**

```json
{
  "username": "alice",
  "password": "Pass1234!",
  "phone": "13800000001",
  "trade_location": "一号门"
}
```

- `username`：1~64 位，全局唯一。
- `password`：8~128 位，且大写字母、小写字母、数字、特殊字符中至少 3 类；不满足返回 422「密码强度不足：至少包含大写字母、小写字母、数字、特殊字符中的 3 类」。
- `phone`：手机号 / 座机均可，允许 `+86`、空格、短横线、括号；保存时归一化为纯数字（如 `+86 138-0000-1234` 存为 `13800001234`）。
- `trade_location`：默认交易地点，1~200 位。

**响应 200**

```json
{
  "customer": {
    "id": "u5e6...", "username": "alice", "phone": "13800000001",
    "trade_location": "一号门", "registered_at": "2026-10-22 09:30:00"
  },
  "message": "注册成功，请登录"
}
```

**错误**：409 `CONFLICT` 用户名已被注册；422 参数校验失败。

### 5.2 POST /api/customer/login —— 客户登录

**请求**

```json
{ "username": "alice", "password": "Pass1234!" }
```

请求头可选带 `X-Guest-Id`；若携带且合法，登录成功后把该游客会话的收藏 / 购物车并入账号。

```json
  "token": "Y3VzdG9tZXIu...",
```

令牌为无状态，服务端仅校验身份，客户端收到成功后自行丢弃令牌。

**响应 200**：`{ "message": "已退出登录" }`

### 5.14 POST /api/customer/orders —— 购物车多选下单

鉴权：客户 Bearer（**下单必须登录**）。

**请求**

```json
{ "product_ids": ["8f1c...", "9a2b..."], "address_id": "a9f8..." }
```

- `product_ids` 必填，去重后 1~50 件，必须是当前客户购物车中的商品。
- `address_id` 选填；不传时带出默认地址，无可用地址返回 409。

**处理逻辑**

1. 逐件校验商品状态与可售数量（可售 = 原始库存 − 活跃占用）；
2. 任一商品不满足条件时**整单失败**并列出全部问题项，提示剔除后重试；
3. 校验通过则生成订单（`PENDING_PAYMENT`）、订单项快照、库存占用（`ACTIVE`），并移除已下单的购物车项；
4. 可售归零的商品自动转 `SOLD_OUT`。

**响应 200**

```json
{
  "order": { "order_no": "20261124-0001", "status": "PENDING_PAYMENT", "status_label": "待支付", "can_pay": true, "...": "..." },
  "message": "下单成功，库存已占用，请在 24 小时内完成支付"
}
```

**错误**

| HTTP | 场景与消息 |
|---|---|
| 422 | 「请至少选择一件商品」 |
| 409 | 「单次下单商品数量不能超过 50 件」 |
| 409 | 「请先在「收货地址」中添加地址后再下单」 |
| 404 | 「收货地址不存在」 |
| 409 | 「以下商品无法下单，请剔除后重试：……」——含「不在购物车中」「商品已不存在」「（已下架/售罄，请剔除）」「（库存不足：需 N 件，可售 M 件，请剔除或调减数量）」 |

### 5.17 POST /api/customer/orders/{order_id}/cancel —— 取消订单

- 允许状态：`PENDING_PAYMENT`、`PAID`、`SELLER_CONFIRMED`、`STOCK_READY`（「开始发货」之前）。
- 取消后订单置 `CANCELLED`，`cancel_by=CUSTOMER`，`cancel_reason=客户主动取消`；
- 已支付（含商家确认、备货完成）的订单自动生成退款单（`refund.status=SUCCESS`，渠道与原支付一致）；
- 逐件释放库存占用（`ACTIVE → RELEASED`），商品可售恢复并自动回到 `ON_SALE`。

**响应 200**

```json
{
  "order": { "status": "CANCELLED", "status_label": "已取消", "cancel_by": "CUSTOMER",
    "cancel_reason": "客户主动取消", "refund": { "refund_no": "RF20261124-0001", "status": "SUCCESS", "...": "..." }, "...": "..." },
  "message": "订单已取消，支付金额已原路退回，占用库存已回补"
}
```

- 未支付订单取消时消息为「订单已取消，占用库存已回补」，`refund` 为 `null`。

**错误**：404 订单不存在；409「订单已「开始发货」，客户无法取消」（`SHIPPING` / `COMPLETED` / `CANCELLED` 同理）。

### 5.18 POST /api/customer/orders/{order_id}/pay —— 发起支付

**请求**

```json
{ "payment_method": "ALIPAY", "simulate_result": "SUCCESS" }
```

- `payment_method` 必填：`BANK_CARD` / `CREDIT_CARD` / `ALIPAY` / `WECHAT`（大小写不敏感）。
- `simulate_result` 选填：`SUCCESS`（默认）或 `FAILED`，仅用于本期模拟支付网关演示失败重试。
- 支付成功：写入支付流水（`SUCCESS` + `transaction_no`），订单转 `PAID`。
- 支付失败：写入支付流水（`FAILED` + `failure_reason`），订单**保持** `PENDING_PAYMENT`，可再次发起。

**响应 200（成功）**

```json
{
```

### 5.19 POST /api/payments/callback —— 支付结果回调（免鉴权）

由支付渠道调用，**无需客户令牌**，签名即凭证。

**请求**

```json
{
  "payment_id": "p2d4...",
  "transaction_no": "TXNA1B2C3D4E5F6G7H8I9J0",
  "status": "SUCCESS",
  "signature": "3f8a...c1"
}
```

- 签名算法：`hex(HMAC_SHA256(secret, payment_id + "|" + status + "|" + transaction_no))`，小写十六进制；`secret` 为服务端令牌密钥（`SHOP_SECRET`）。
- 验签采用常量时间比较，失败返回 401。
- 幂等：支付记录已是 `SUCCESS` 时直接返回当前状态并标记 `idempotent=true`，不重复改单。

**响应 200**

```json
{
  "payment": { "status": "SUCCESS", "...": "..." },
  "idempotent": false,
  "message": "回调处理完成"
}
```

**错误**：401「支付回调签名校验失败」；404「支付记录不存在」；422「回调缺少支付单号或状态」/「回调状态需为 SUCCESS 或 FAILED」。

> 除登录外均需 `Authorization: Bearer <卖家令牌>`。卖家为系统内置固定账号，**无注册、无退出登录接口**（FR-036）。

### 6.1 POST /api/seller/login —— 卖家登录

**请求**：`{ "username": "seller", "password": "seller123" }`

**响应 200**

```json
{
  "token": "c2VsbGVy...",
  "token_type": "Bearer",
  "expires_at": 1792819200,
```

### 6.2 POST /api/seller/password —— 修改密码

鉴权：卖家 Bearer。修改成功后当前令牌继续有效，不会强制下线（FR-036）。

**请求**

```json
{ "old_password": "seller123", "new_password": "Newpass1!" }
```

| 字段 | 校验规则 | 不满足时 |
|---|---|---|
| `old_password` | 必填；去除首尾空白后 1~128 个字符；须与当前密码完全一致（区分大小写） | 缺失/空白/超长 → 422 `VALIDATION_ERROR`；与当前密码不一致 → 401 `UNAUTHORIZED`，消息“旧密码不正确” |
| `new_password` | 必填；去除首尾空白后 **8~128 个字符**（FR-037 / C-29），按字符数计算，且大写字母、小写字母、数字、特殊字符中**至少包含 3 类** | 缺失/仅空白 → 422，消息“新密码不能为空”；少于 8 位 → 422，消息“新密码长度不能少于 8 个字符”；超过 128 位 → 422，消息“新密码长度不能超过 128 个字符”；强度不足 → 422，消息“密码强度不足：至少包含大写字母、小写字母、数字、特殊字符中的 3 类” |

- 新密码不足 8 位（如 6 位、7 位）或强度不足（如纯数字 `12345678`、纯字母 `abcdefgh`、仅小写+数字 `pass1234`）一律返回 422，不会写入数据库；请求在事务内校验并更新，失败时原密码保持不变。
- 密码以 PBKDF2-SHA256 哈希存储，接口响应不返回密码或哈希。

**响应 200**

```json
{ "message": "密码修改成功" }
```

**错误**

| HTTP | code | 场景 |
|---|---|---|
| 401 | `UNAUTHORIZED` | 未携带令牌、令牌失效、身份非卖家、旧密码不正确 |
| 422 | `VALIDATION_ERROR` | 新旧密码为空、新密码少于 8 位、超过 128 位或字符类别不足 3 类；`details` 中给出字段位置与原因 |

### 6.16 POST /api/seller/intents/{intent_id}/transaction —— 标记交易结果

**请求**

```json
{ "result": "SUCCESS", "note": "买家已提货" }
```

```json
{ "result": "FAILED", "note": "买家未到场", "failed_action": "REQUEUE" }
```

- `result`：`SUCCESS` 或 `FAILED`。
- `note`：≤500 字符，可选。
- `failed_action`：`result=FAILED` 时**必填**，取 `VOID`（作废失败者）或 `REQUEUE`（重新排到队尾，不限次数）（FR-030）。
- 只有 `IN_TRANSACTION` 的意向可以标记结果。

**成功（SUCCESS）**

- 意向置 `SUCCESS`，写入交易记录，库存 **减 1**（FR-013/028）。
- 库存减至 0：商品置 `SOLD_OUT`，剩余排队意向置 `SOLD_OUT`（售罄作废）并清空队列（FR-014/034）。
- 库存仍 >0：商品恢复 `ON_SALE`，继续接收意向。

**失败（FAILED）**

- 库存**不变**，商品立即恢复 `ON_SALE`（库存为 0 时保持 `SOLD_OUT`）。
- `failed_action=VOID`：该意向置 `VOIDED`。
- `failed_action=REQUEUE`：该意向重新排到**队尾**，置 `REQUEUED`，`requeue_count+1`。
- **无自动递补**：下一位不会自动进入交易，需卖家再次调用 start-transaction。
- 失败处理与标记失败在同一请求内完成；缺少 `failed_action` 时返回 422 且**整个事务回滚**（不产生交易记录、不改状态）。

**响应 200**

```json
{
```

## 8. 端到端业务时序

### 8.1 正常成交（买家端视角）

```
客户登录 → 浏览商品（stock 为可售数量）
 → 加入购物车（不占库存）→ 新增/选择收货地址
 → POST /orders 多选下单（逐件校验可售，占用库存，订单 PENDING_PAYMENT，购物车项移除）
 → POST /orders/{id}/pay（ALIPAY，SUCCESS）→ 订单 PAID
 → 商家确认 SELLER_CONFIRMED → 备货完成 STOCK_READY → 开始发货 SHIPPING（填写物流服务商与运单号）
 → 客户 GET /orders/{id}/shipment 查看轨迹 → 商家确认签收后订单 COMPLETED
 → 客户 POST /after-sales 对某订单项发起售后
```

### 8.2 支付失败与重试

```
订单 PENDING_PAYMENT
POST /pay {payment_method: WECHAT, simulate_result: FAILED}
  → 写入 payment(FAILED, failure_reason="支付渠道返回失败（模拟）")
  → 订单仍为 PENDING_PAYMENT，can_pay=true，可再次发起
POST /pay {payment_method: WECHAT}（simulate_result 默认 SUCCESS）→ 订单 PAID
```

### 8.3 客户取消与退款

```
情况 A：待支付取消
  PENDING_PAYMENT → POST /orders/{id}/cancel
  → 订单 CANCELLED，cancel_by=CUSTOMER；占用 RELEASED，可售回补；无退款单

情况 B：已支付（或商家确认 / 备货完成）取消
  PAID → POST /orders/{id}/cancel
  → 订单 CANCELLED；按最近一条成功支付生成 refund(SUCCESS, 原渠道, 全额)
  → 占用 RELEASED，可售回补；商品可售 > 0 时自动回到 ON_SALE

情况 C：已开始发货
  SHIPPING / COMPLETED / CANCELLED → POST /orders/{id}/cancel
  → 409「订单已「开始发货」，客户无法取消」
```

### 8.4 待支付超时自动取消

```
下单后超过 24 小时仍未支付
→ OrderTimeoutJob 每 5 分钟扫描一次（启动后 30 秒首跑）
→ 命中 status=PENDING_PAYMENT 且 created_at ≤ now-24h 的订单：
   订单 CANCELLED，cancel_by=SYSTEM，cancel_reason 含「超过 24 小时未支付」
   占用 RELEASED，可售回补，商品状态自动刷新
```

### 8.5 支付回调验签与幂等

```
模拟网关 → POST /api/payments/callback
  signature ≠ HMAC_SHA256(secret, payment_id|status|transaction_no) → 401，支付记录不变
  签名正确且支付记录非 SUCCESS → 更新状态与交易号；SUCCESS 时订单 PENDING_PAYMENT → PAID
  支付记录已 SUCCESS → 返回 idempotent=true，不重复改单
```

### 8.6 售后申请与结果

```
订单 COMPLETED
→ 客户 POST /after-sales（order_item_id + 标题 + 描述 + 最多 9 张图片）
→ 售后单 PENDING（AS 单号），客户可在列表中按状态筛选
→ 商家线下协商，推进 NEGOTIATING → RESOLVED / REJECTED，并记录 result（退货/退款/换货）与 result_note
→ 客户 GET /after-sales/{id} 查看处理结果
```

### 8.7 库存一致性

```
下单：stock_reservation(ACTIVE)            → 可售 = stock − ΣACTIVE
取消：ACTIVE → RELEASED                    → 可售回补
完成：ACTIVE → CONSUMED（卖家端推进）      → 原始库存实扣
并发：SQLite WAL + 单写事务（BEGIN IMMEDIATE）串行化，避免超卖
```
