# 接口设计文档

**项目：** 在线购物系统（单商家 · 挑战A升级版）
**角色：** 成员2 —— 后端开发岗
**版本：** V2.0
**日期：** 2026-10-22
**框架：** Spring Boot 2.7.18（Java 8）+ springdoc-openapi 1.6.15（OpenAPI 3.0）
**在线文档：** `http://127.0.0.1:8000/docs`（Swagger UI）；`http://127.0.0.1:8000/redoc` 自动跳转至 `/docs`

> 本版本依据《需求规格说明书-挑战A升级版》重写。相较 V1.0：商品由"单件在售"升级为多商品同时在售；新增二级类别、库存、多图、富媒体描述、客户账号体系；**删除口令码、匿名意向、买家撤销/修改、自动递补**；交易失败改为"标记失败 + 同步选择失败者处理"的单动作模型。

## 1. 通用约定

| 项目 | 约定 |
|---|---|
| Base URL | `http://127.0.0.1:8000` |
| 编码 | 请求/响应体统一 UTF-8，`Content-Type: application/json` |
| 时间格式 | `YYYY-MM-DD HH:MM:SS`（本地时间字符串） |
| 金额 | 出参 `price` 为元（保留 2 位小数，数值类型），同时给出 `price_cents`（整数分）；入参 `price` 为元，必须 > 0 且最多两位小数 |
| 鉴权 | `Authorization: Bearer <token>`；卖家接口需卖家令牌，客户下单/意向/历史/账号接口需客户令牌，公开浏览与搜索免鉴权 |
| 令牌 | 无状态 HMAC-SHA256 令牌，载荷内含角色（`seller` / `customer`）；跨角色调用返回 401 |
| 分页 | 查询参数 `page`（≥1，默认 1）、`page_size`（1~100，默认 10） |
| 错误格式 | 统一 `{"error": {"code": "...", "message": "..."}}`，校验错误额外带 `details` |

### 1.1 错误码

| HTTP | code | 含义 |
|---|---|---|
| 400 | `BUSINESS_ERROR` | 通用业务错误 |
| 400 | `INVALID_IMAGE_FORMAT` | 商品图片格式不是 JPG / PNG |
| 400 | `IMAGE_TOO_LARGE` | 图片超过 5MB |
| 400 | `INVALID_MEDIA_FORMAT` | 富媒体文件格式不支持 |
| 400 | `MEDIA_TOO_LARGE` | 富媒体文件超过大小限制 |
| 400 | `EMPTY_FILE` | 上传文件为空 |
| 401 | `UNAUTHORIZED` | 未登录 / 令牌无效或过期 / 角色不符 / 旧密码错误 |
| 404 | `NOT_FOUND` | 资源不存在（商品、类别、意向、客户） |
| 409 | `CONFLICT` | 状态冲突（重复注册、重复意向、交易中、库存/队列条件不满足等） |
| 422 | `VALIDATION_ERROR` | 请求参数校验失败（如库存为负、未选二级类别、失败未指定处理方式） |

**错误响应示例**

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "库存不能为负数",
    "details": [
      { "loc": ["body", "stock"], "msg": "库存不能为负数", "type": "value_error" }
    ]
  }
}
```

### 1.2 状态取值

| 类别 | 取值 |
|---|---|
| 商品状态 | `ON_SALE`（在售）、`FROZEN`（交易中/已冻结）、`SOLD_OUT`（已售罄下架）、`OFF_SHELF`（已手动下架） |
| 意向状态 | `QUEUED`（排队中）、`REQUEUED`（重新排队中）、`IN_TRANSACTION`（已进入交易）、`SUCCESS`（交易成功）、`FAILED`（交易失败）、`VOIDED`（已作废）、`SOLD_OUT`（售罄失效） |
| 交易结果 | `SUCCESS`（交易成功）、`FAILED`（交易失败） |
| 失败者处理 | `VOID`（作废）、`REQUEUE`（重新排到队尾） |

> 商品的 `FROZEN` 有两种来源：卖家手动冻结、系统与队首买家进入交易时自动冻结。商品对外仍可见（公开列表包含 `ON_SALE` 与 `FROZEN`），但 `can_buy` 为 `false`。

## 3. 公共数据结构

### 3.1 商品对象 product

```json
{
  "id": "8f1c2a7e4b6d4c0e9a3f5d2b1c8e7f60",
  "name": "手工陶瓷杯",
  "description": "<p>手作限量</p><img src=\"/uploads/6d2f.png\">",
  "price": 99.9,
  "price_cents": 9990,
  "stock": 2,
  "status": "ON_SALE",
  "status_label": "在售",
  "category_id": "c2b7...",
  "category_name": "杯子",
  "parent_category_id": "a1d9...",
  "parent_category_name": "厨房用品",
  "published_at": "2026-10-22 10:00:00",
  "created_at": "2026-10-22 10:00:00",
  "updated_at": "2026-10-22 10:05:00",
  "images": [
    { "id": "img01", "url": "/uploads/ab12.jpg", "sort_order": 1 },
    { "id": "img02", "url": "/uploads/cd34.png", "sort_order": 2 }
  ],
  "primary_image": "/uploads/ab12.jpg",
  "image_count": 2
}
```

- `images` 按 `sort_order` 升序，第 1 张即主图 `primary_image`；无图时 `primary_image` 为 `null`、`image_count` 为 0。
- `description` 为富文本 HTML，内嵌资源均为 `/uploads/...` 本地上传地址。

### 3.2 意向对象 intent

```json
{
  "id": "b7d2c1a0e9f84d6b8c3a2f1e0d9c8b7a",
  "product_id": "8f1c...",
  "customer_id": "u5e6...",
  "status": "QUEUED",
  "status_label": "排队中",
  "queue_position": 1,
  "requeue_count": 0,
  "created_at": "2026-10-22 10:05:00",
  "updated_at": "2026-10-22 10:05:00"
}
```

卖家侧（排队名单、交易响应、历史详情）会在意向对象上附加 `customer` 字段：

```json
{
  "customer": {
    "id": "u5e6...",
    "username": "alice",
    "phone": "13800000001",
    "trade_location": "一号门",
    "registered_at": "2026-10-22 09:30:00"
  }
}
```

### 3.3 客户对象 customer

```json
{
  "id": "u5e6...",
  "username": "alice",
  "phone": "13800000001",
  "trade_location": "一号门",
  "registered_at": "2026-10-22 09:30:00"
}
```

> 客户信息仅在客户本人接口与卖家授权接口中返回；公开接口不返回任何客户信息（NFR-004）。

### 3.4 类别对象 category

```json
{
  "id": "a1d9...",
  "name": "厨房用品",
  "parent_id": null,
  "level": 1,
  "created_at": "2026-10-22 09:00:00",
  "updated_at": "2026-10-22 09:00:00",
  "product_count": 0,
  "children": [
    {
      "id": "c2b7...",
      "name": "杯子",
      "parent_id": "a1d9...",
      "level": 2,
      "created_at": "2026-10-22 09:01:00",
      "updated_at": "2026-10-22 09:01:00",
      "product_count": 2
    }
  ]
}
```

- 类别固定两级：`level=1` 为一级（大类），`level=2` 为二级（小类）。
- 类别树接口中仅一级类别带 `children`；`product_count` 为该类别直接挂载的商品数。
- 商品必须挂二级类别；已发布商品的类别不随类别改名而变化。

### 3.5 交易记录对象 trade

```json
{
  "id": "t9a1...",
  "intent_id": "b7d2...",
  "product_id": "8f1c...",
  "customer_id": "u5e6...",
  "result": "SUCCESS",
  "result_label": "交易成功",
  "note": null,
  "created_at": "2026-10-22 11:00:00"
}
```

### 3.6 交易汇总对象 transaction_summary

```json
{
  "failed_rounds": 2,
  "buyer_count": 4,
  "final_result": "SUCCESS",
  "final_result_label": "交易成功",
  "last_transaction_at": "2026-10-22 11:00:00"
}
```

- `failed_rounds`：该商品交易失败次数（多次失败全部保留）。
- `buyer_count`：提交过意向的去重客户数。
- `final_result`：最近一条交易记录的结果；无交易记录时为 `null`，`final_result_label` 为 `"未成交"`。

## 4. 公开接口

### 4.1 GET /api/products —— 商品列表 / 搜索

**查询参数**

| 参数 | 必填 | 说明 |
|---|---|---|
| `page` | 否 | 页码，默认 1 |
| `page_size` | 否 | 每页条数，1~100，默认 10 |
| `keyword` | 否 | 按商品名称模糊匹配 |
| `category_id` | 否 | 类别筛选；传一级类别时自动包含其全部二级类别 |

- 仅返回 `ON_SALE`（在售）与 `FROZEN`（交易中）商品，按发布时间倒序。
- 游客与客户均可访问，无需登录（FR-019）。

**响应 200**

```json
{
  "items": [ { "id": "8f1c...", "name": "手工陶瓷杯", "stock": 2, "status": "ON_SALE", "...": "..." } ],
  "total": 2,
  "page": 1,
  "page_size": 10
}
```

### 4.2 GET /api/products/{product_id} —— 商品详情

**响应 200**

```json
{
  "product": { "id": "8f1c...", "name": "手工陶瓷杯", "stock": 2, "images": ["..."], "...": "..." },
  "queue_count": 3,
  "can_buy": true
}
```

- `queue_count`：当前该商品队列人数。
- `can_buy`：商品为 `ON_SALE` 且 `stock > 0` 时为 `true`。
- **错误**：404 `NOT_FOUND` —— 商品不存在或已手动下架（`OFF_SHELF`）。`SOLD_OUT` 商品仍可查看详情，但 `can_buy=false`。

### 4.3 GET /api/categories —— 类别树

**响应 200**

```json
{ "items": [ { "id": "a1d9...", "name": "厨房用品", "level": 1, "children": [ { "id": "c2b7...", "name": "杯子", "level": 2 } ] } ] }
```

### 4.4 GET / —— 服务信息

**响应 200**

```json
{ "name": "single-merchant-shop backend", "version": "1.0.0", "docs": "/docs", "redoc": "/redoc" }
```

## 5. 客户接口

### 5.1 POST /api/customer/register —— 客户注册

**请求**

```json
{
  "username": "alice",
  "password": "pass1234",
  "phone": "13800000001",
  "trade_location": "一号门"
}
```

- `username`：1~64 位，全局唯一。
- `password`：6~128 位。
- `phone`：5~20 位，允许数字、`+`、`-`、空格。
- `trade_location`：默认交易地点，1~200 位。

**响应 200**

```json
{
  "customer": {
    "id": "u5e6...", "username": "alice", "phone": "13800000001",
    "trade_location": "一号门", "registered_at": "2026-10-22 09:30:00"
  },
  "message": "注册成功，请登录"
}
```

**错误**：409 `CONFLICT` 用户名已被注册；422 参数校验失败。

### 5.2 POST /api/customer/login —— 客户登录

**请求**：`{ "username": "alice", "password": "pass1234" }`

**响应 200**

```json
{
  "token": "Y3VzdG9tZXIu...",
  "token_type": "Bearer",
  "expires_at": 1792819200,
  "customer": { "id": "u5e6...", "username": "alice", "phone": "13800000001", "...": "..." }
}
```

**错误**：401 `UNAUTHORIZED` 用户名或密码错误。

### 5.3 POST /api/customer/logout —— 客户登出

鉴权：客户 Bearer。令牌为无状态，服务端仅校验身份，客户端收到成功后自行丢弃令牌。

**响应 200**：`{ "message": "已退出登录" }`

**错误**：401 未登录或令牌失效。

### 5.4 GET /api/customer/me —— 个人资料

**响应 200**

```json
{
  "customer": { "id": "u5e6...", "username": "alice", "phone": "13800000001",
    "trade_location": "一号门", "registered_at": "2026-10-22 09:30:00" },
  "purchase_count": 1
}
```

- `purchase_count`：该客户交易成功（`SUCCESS`）的订单数。

### 5.5 POST /api/customer/password —— 修改密码

**请求**：`{ "old_password": "pass1234", "new_password": "newpass123" }`

- 新密码 6~128 位。

**响应 200**：`{ "message": "密码修改成功" }`

**错误**：401 旧密码不正确 / 未登录。

### 5.6 POST /api/customer/intents —— 提交购买意向

鉴权：客户 Bearer（**未登录不能下单**，FR-020）。

**请求**

```json
{ "product_id": "8f1c..." }
```

**响应 200**

```json
{
  "intent": {
    "id": "b7d2...", "product_id": "8f1c...", "customer_id": "u5e6...",
    "status": "QUEUED", "status_label": "排队中",
    "queue_position": 2, "requeue_count": 0,
    "created_at": "2026-10-22 10:05:00", "updated_at": "2026-10-22 10:05:00"
  },
  "product": { "id": "8f1c...", "stock": 2, "status": "ON_SALE", "...": "..." },
  "queue_position": 2,
  "message": "已进入该商品队列，请耐心等待卖家处理"
}
```

- 每个商品独立队列，按提交时间先到先得（FR-022/023）；排队人数不限（FR-024）。
- 同一客户在同一商品上只能有一个有效意向（`QUEUED` / `REQUEUED` / `IN_TRANSACTION`）。

**错误**

| HTTP | 场景 |
|---|---|
| 401 | 未登录 / 令牌失效 / 非客户身份 |
| 404 | 商品不存在 |
| 409 | 商品已下架 / 已售罄 / 交易中 / 库存为 0 / 重复提交（"您已在该商品的队列中，请勿重复提交"） |

### 5.7 GET /api/customer/intents —— 我的意向列表

**查询参数**：`page`、`page_size`、`status`（可选，意向状态枚举）。

**响应 200**

```json
{
  "items": [
    {
      "id": "b7d2...", "status": "SUCCESS", "status_label": "交易成功",
      "queue_position": 1, "requeue_count": 0,
      "created_at": "2026-10-22 10:05:00", "updated_at": "2026-10-22 11:00:00",
      "product": { "id": "8f1c...", "name": "手工陶瓷杯", "...": "..." },
      "transaction": { "result": "SUCCESS", "result_label": "交易成功", "...": "..." }
    }
  ],
  "total": 1,
  "page": 1,
  "page_size": 10
}
```

- 按提交时间倒序；`transaction` 为该意向最近一条交易记录，未交易时为 `null`。
- 客户只能查看自己的意向，**不提供撤销、修改入口**（FR-025）。

### 5.8 GET /api/customer/intents/{intent_id} —— 意向详情

**响应 200**：单条意向对象（含 `product` 与 `transaction`）。

**错误**：404 `NOT_FOUND` 意向不存在或不属于当前客户（越权按不存在处理）。

### 5.9 GET /api/customer/orders —— 历史下单记录

**查询参数**：`page`、`page_size`。

**错误**：404 商品不存在；409 非冻结态 / 存在进行中的交易 / 库存为 0。

### 6.16 POST /api/seller/intents/{intent_id}/transaction —— 标记交易结果

**请求**

```json
{ "result": "SUCCESS", "note": "买家已提货" }
```

```json
{ "result": "FAILED", "note": "买家未到场", "failed_action": "REQUEUE" }
```

- `result`：`SUCCESS` 或 `FAILED`。
- `note`：≤500 字符，可选。
- `failed_action`：`result=FAILED` 时**必填**，取 `VOID`（作废失败者）或 `REQUEUE`（重新排到队尾，不限次数）（FR-030）。
- 只有 `IN_TRANSACTION` 的意向可以标记结果。

**成功（SUCCESS）**

- 意向置 `SUCCESS`，写入交易记录，库存 **减 1**（FR-013/028）。
- 库存减至 0：商品置 `SOLD_OUT`，剩余排队意向置 `SOLD_OUT`（售罄作废）并清空队列（FR-014/034）。
- 库存仍 >0：商品恢复 `ON_SALE`，继续接收意向。

**失败（FAILED）**

- 库存**不变**，商品立即恢复 `ON_SALE`（库存为 0 时保持 `SOLD_OUT`）。
- `failed_action=VOID`：该意向置 `VOIDED`。
- `failed_action=REQUEUE`：该意向重新排到**队尾**，置 `REQUEUED`，`requeue_count+1`。
- **无自动递补**：下一位不会自动进入交易，需卖家再次调用 start-transaction。
- 失败处理与标记失败在同一请求内完成；缺少 `failed_action` 时返回 422 且**整个事务回滚**（不产生交易记录、不改状态）。

**响应 200**

```json
{
  "intent": {
    "id": "b7d2...", "status": "REQUEUED", "status_label": "重新排队中",
    "queue_position": 2, "requeue_count": 1,
    "customer": { "id": "u5e6...", "username": "alice", "phone": "13800000001" }
  },
  "product": { "id": "8f1c...", "status": "ON_SALE", "stock": 2, "...": "..." },
  "message": "交易失败，库存不变，商品恢复在售；该买家已重新排到队尾（第 2 位）"
}
```

**错误**

| HTTP | 场景 |
|---|---|
| 404 | 意向单不存在 |
| 409 | 仅进行中的交易可以标记结果 |
| 422 | `result` 非法 / 失败未指定 `failed_action` / `failed_action` 非法 |

## 8. 端到端业务时序

### 8.1 正常成交（库存 > 1）

```
卖家登录 → 创建二级类别 → 发布商品(ON_SALE, stock=2, 多图)
客户A登录 → 提交意向 → 队列 1（QUEUED）
客户B登录 → 提交意向 → 队列 2（QUEUED）
卖家 start-transaction → A 进入交易(IN_TRANSACTION)，商品 FROZEN
卖家 mark(SUCCESS) → A=SUCCESS；stock=1；商品恢复 ON_SALE，可继续接收意向
```

### 8.2 库存归零（售罄下架）

```
商品 stock=1；队列 A(1)、B(2)
start-transaction → A 进入交易，商品 FROZEN
mark(SUCCESS) → A=SUCCESS；stock 减为 0 → 商品 SOLD_OUT；B 置 SOLD_OUT（售罄作废）；清空队列
卖家 GET /history/{id} → 交易汇总 final_result=SUCCESS
补货 PATCH stock=5 → 商品自动恢复 ON_SALE
```

### 8.3 交易失败 + 失败者作废（VOID）

```
队列 A(1)、B(2)；start-transaction → A 进入交易，商品 FROZEN
mark(FAILED, failed_action=VOID)
  → 写入 FAILED 交易记录；库存不变；商品恢复 ON_SALE；A=VOIDED
  → B 仍在队列第 1 位，不自动进入交易
卖家再次 start-transaction → B 进入交易
```

### 8.4 交易失败 + 重新排队（REQUEUE）

```
队列 A(1)、B(2)；start-transaction → A 进入交易
mark(FAILED, failed_action=REQUEUE)
  → A 重新排到队尾第 2 位，状态 REQUEUED，requeue_count+1
  → 商品恢复 ON_SALE，库存不变
REQUEUE 不限次数
```

### 8.5 冻结/解冻与手动上下架

```
手动冻结(FROZEN)：暂停接收新意向，已有队列保留
手动解冻(ON_SALE)：无进行中交易且库存>0 时恢复
手动下架(OFF_SHELF)：排队意向全部 VOIDED，清空队列
重新上架(ON_SALE)：仅 OFF_SHELF 且库存>0
库存调为 0(SOLD_OUT)：排队意向全部 SOLD_OUT
库存调为 >0：SOLD_OUT/OFF_SHELF 自动恢复 ON_SALE
```
