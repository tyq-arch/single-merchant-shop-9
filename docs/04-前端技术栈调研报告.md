# 前端技术栈调研报告

**项目：** 在线购物系统（单卖家版）
**角色：** 成员3 —— 前端开发岗
**版本：** V1.0
**日期：** 2026-10-07

---

## 1. 调研目标与范围

本报告为前端选型提供依据，覆盖前端框架、构建工具、路由与状态管理、UI 方案、HTTP 封装、移动端适配与联调方案。
选型需满足需求文档与接口文档中的关键约束：

| 需求编号 | 约束要点 | 对选型的影响 |
|---|---|---|
| FR-051 / FR-052 | 卖家后台 Web + 买家 Web/H5 双端 | 一套工程要能承载两种布局风格（桌面管理台 vs 移动端页面） |
| FR-052 / NFR-008 | 买家端响应式适配，主流浏览器可用 | 买家端需移动优先的响应式方案 |
| FR-043~FR-046 | 买家端商品三态展示（无货 / 在售 / 交易中） | 需要清晰的状态分支渲染，文案由后端下发 |
| FR-044 / FR-046 | 「暂无商品在售」「商品交易中」强约束文案 | 文案不可自行改写，需直接取后端 `message` 字段 |
| FR-048 / FR-050 | 口令码当场展示、强提示保存、丢失不可找回 | 需要醒目的口令码展示页 + 复制按钮 + 二次确认 |
| NFR-002 | 防 XSS / CSRF | 框架默认转义，避免 `v-html` 直接渲染用户输入 |
| NFR-004 | 口令码不可枚举 | 口令码不应长期停留在 URL 与浏览器历史中 |
| NFR-009 | 模块化、可维护 | 需要分层目录与统一请求封装 |

**范围说明：** 本报告只覆盖前端浏览器端。后端已定型为 FastAPI + SQLite（见 `01-技术栈调研报告.md`），前端不引入 Node 服务端渲染，不引入独立的 BFF 层。

## 2. 前端框架方案对比

| 维度 | Vue 3 + Vite（采用） | React + Vite | 纯静态 HTML/CSS/JS | Vue 2 + Webpack |
|---|---|---|---|---|
| 上手成本 | 低，模板语法接近 HTML | 中，JSX 与 Hooks 需适应 | 最低 | 低（但生态已停止演进） |
| 双侧路由支持 | 好，`vue-router` 嵌套路由天然适配「买家端 / 卖家后台」 | 好，React Router 嵌套路由 | 需手写多页面跳转 | 好 |
| 状态管理 | Pinia，API 简洁 | Redux / Zustand | 需自行用全局变量 | Vuex |
| 表格/表单组件 | Element Plus 成熟 | Ant Design 成熟 | 需手写，工作量大 | Element UI |
| 响应式（买家 H5） | 强，`<style scoped>` + 媒体查询 | 同 | 同 | 同 |
| 构建速度 | 极快（esbuild/Rollup） | 极快 | 无构建 | 慢 |
| 生产部署 | `npm run build` 产出静态文件，任意静态服务器可托管 | 同 | 无构建，直接托管 | 同 |
| 本机环境 | **Node v24.10.0 + npm 11.6.1 已就绪** | 已就绪 | 已就绪 | 已就绪 |
| 团队学习成本 | 低，中文资料最丰富 | 中 | 低 | 低（但已过时） |
| 结论 | **采用** | 备选 | 不采用 | 不采用 |

**决策理由：**

1. **本机 Node 环境已就绪。** 后端调研报告（2026-10-05）记录的「未安装 Node」已不成立，复测结果为 Node v24.10.0、npm 11.6.1，Vite 可直接运行，前端构建不再有环境障碍；
2. **双端形态差异大，需要路由分层。** 卖家后台是桌面管理台（表格、分页、对话框），买家端是移动 H5（单列卡片、大按钮）。`vue-router` 的嵌套路由可以用一个工程、两套布局承载，避免维护两个项目；
3. **模板语法降低团队阅读门槛。** 项目为课程 Scrum 项目，成果物需全员理解、组长汇总、答辩演示，Vue 的单文件组件（`<template>/<script>/<style>` 三段式）比 JSX 更直观；
4. **Element Plus 直接覆盖后台的高频组件。** 意向购买人列表、历史商品列表都需要分页表格，手写成本高且样式难统一；
5. **纯静态方案不采纳。** 本系统有 13 个页面且共享鉴权状态（卖家令牌）与状态标签映射，多页面跳转会导致重复代码与状态丢失，可维护性差（违背 NFR-009）。

## 3. 关键子方案

### 3.1 构建工具：Vite

| 项目 | 选择 | 说明 |
|---|---|---|
| 构建/开发服务器 | Vite 8.3.3 | 冷启动毫秒级，热更新快，适合迭代演示 |
| 开发端口 | `5173` | 默认端口，与后端 `8000` 并存 |
| 生产构建 | `npm run build` → `dist/` | 纯静态产物，可由 Nginx 或 FastAPI `StaticFiles` 托管 |
| 路径别名 | `@` → `src/` | 避免 `../../..` 相对路径 |

### 3.2 开发期跨域：Vite Dev Server 代理

后端已开启 `allow_origins=["*"]`（见 `backend/app/main.py`），理论上可直接跨域访问。但前端仍统一走开发代理，理由：

- 请求路径统一为 `/api/...`，**开发环境与生产环境前端代码零差异**；
- 生产部署时前端与后端同源，无需再次调整；
- 规避浏览器对跨域预检（`OPTIONS`）的额外往返。

```js
// vite.config.js
server: {
  port: 5173,
  proxy: {
    '/api':     { target: 'http://127.0.0.1:8000', changeOrigin: true },
    '/uploads': { target: 'http://127.0.0.1:8000', changeOrigin: true }, // 商品主图静态资源
  },
}
```

### 3.3 路由：Vue Router

| 项目 | 方案 | 对应需求 |
|---|---|---|
| 路由模式 | `createWebHistory`（HTML5 History） | 路径美观，便于演示与截图 |
| 布局分层 | 买家端 `BuyerLayout`（移动优先）/ 卖家端 `SellerLayout`（含侧边导航） | FR-051 / FR-052 |
| 登录守卫 | `/seller/*` 除 `login` 外全部走 `beforeEach` 校验令牌 | FR-032 |
| 令牌失效 | 请求返回 401 时清除令牌并跳转登录页 | FR-032 |
| 首屏兜底 | 未匹配路由重定向到买家端首页 | — |

> ⚠️ **无退出登录路由。** 需求 FR-034 明确规定后台不提供退出登录功能，因此**不设计 `/logout` 路由、后台不放置退出按钮**。令牌仅通过有效期自然失效（`SHOP_TOKEN_TTL_SECONDS`）。

### 3.4 状态管理：Pinia

| Store | 职责 | 持久化 |
|---|---|---|
| `useSellerStore` | 卖家令牌、令牌过期时间、卖家用户名 | `localStorage`（刷新后台不丢登录态） |
| `useBuyerStore` | 当前口令码、意向详情、`can_edit` / `can_cancel` 标志 | `sessionStorage`（关闭标签页即清除） |

**令牌存储的取舍：** 令牌存 `localStorage` 而非 Cookie，是为了让后端保持无状态令牌方案（HMAC 签名，见后端技术栈报告第 4 节），无需引入 CSRF 令牌机制。代价是需防范 XSS，因此全站**禁止 `v-html` 渲染任何用户可控内容**（商品名称、描述、买家姓名）。

**口令码存储的取舍：** 口令码等价于买家的唯一凭证（NFR-004 要求不可枚举）。若把口令码写进路由路径（`/intent/:code`），它会留在浏览器历史记录与地址栏中，他人可直接翻历史记录窃取。因此：

- 提交成功页与意向详情页的路径**不含口令码**（`/success`、`/intent`）；
- 口令码存 `sessionStorage`，刷新可恢复，关闭标签页自动清除；
- 页面提供「退出查询」入口，主动清除 `sessionStorage` 中的口令码。

### 3.5 HTTP 请求：axios 统一封装

需求与接口文档约定错误格式统一为 `{"error": {"code", "message"}}`，因此封装一个实例做三件事：注入令牌、解包响应、归一化错误。

| 处理点 | 方案 |
|---|---|
| Base URL | `/api`（走 Vite 代理） |
| 令牌注入 | 请求拦截器补 `Authorization: Bearer <token>` |
| 成功响应 | 直接返回 `response.data`，业务层不再写 `.data` |
| 错误归一化 | 解析 `error.message` 抛出，业务层只拿到可展示的中文文案 |
| 401 处理 | 响应拦截器清除令牌，跳转 `/seller/login` |
| 超时 | 10 秒（NFR-001 要求商品详情 < 2 秒） |
| 文件上传 | `multipart/form-data`，字段名 `file`；前端预校验扩展名与 ≤5MB |

**关键约定：状态文案一律取后端下发的 `status_label` / `result_label` / `message`，前端不自建中文映射表。** 后端已为商品状态、意向状态、交易结果提供了中文标签（见 `backend/app/enums.py`），前端重复维护会产生不一致风险。

### 3.6 UI 方案：分端选型

| 端 | 方案 | 理由 |
|---|---|---|
| 卖家后台 | **Element Plus 2.14.7** | 分页表格、表单校验、对话框、上传、消息提示均为现成组件，减少重复实现 |
| 买家端 H5 | **手写 CSS（移动优先 + 媒体查询）** | 仅 5 个页面，组件库对移动端单列卡片布局帮助有限，反而增加包体积；手写便于体现视觉设计与「UI 布局美化」工作量 |

> 备选方案：若评审要求统一风格，可将买家端改用 Vant 4；若要求全手写，可移除 Element Plus 自建后台表格组件。当前方案为两者折中。

### 3.7 移动端适配

| 项目 | 方案 |
|---|---|
| 视口 | `<meta name="viewport" content="width=device-width, initial-scale=1">` |
| 断点 | 移动 `<768px` / 平板 `768–1024px` / 桌面 `≥1024px` |
| 买家端 | 单列流式布局，最大宽度 640px 居中，触控目标 ≥ 44px |
| 卖家后台 | 桌面优先，窄屏时侧边导航折叠为顶部标签 |
| 图片 | `object-fit: cover` + 固定宽高比容器，防止上传图尺寸不一导致布局跳动 |

### 3.8 表单校验

前端校验规则必须与后端 Pydantic 模型（`backend/app/schemas.py`）保持一致，仅在提交前拦截明显错误以改善体验，**最终校验以后端为权威**（422 `VALIDATION_ERROR`）。

| 字段 | 前端校验 | 后端对应 |
|---|---|---|
| 买家姓名 | 必填，去空格后非空，≤64 字 | `BuyerIntentCreateRequest._check_name` |
| 联系电话 | 必填，5–20 位，仅允许数字、`+`、`-`、空格 | 正则 `^[0-9+\-\s]{5,20}$` |
| 修改信息 | 姓名与电话至少填一项 | `BuyerIntentUpdateRequest._at_least_one` |
| 商品名称 | 必填，≤120 字 | `ProductCreateRequest.name` |
| 商品价格 | 必填，> 0 且 ≤ 9999999，保留 2 位小数 | `ProductCreateRequest.price` |
| 商品描述 | 选填，≤2000 字 | `ProductCreateRequest.description` |
| 主图 | 选填，jpg/jpeg/png/gif/webp，≤5MB | `POST /api/files/images` |
| 旧密码 / 新密码 | 均必填；新密码 6–128 位 | `ChangePasswordRequest` |
| 交易失败备注 | 选填，≤500 字 | `TransactionMarkRequest.note` |

## 6. 环境要求与搭建步骤

**环境要求：** Node.js ≥ 20（本机 v24.10.0）、npm ≥ 10（本机 11.6.1）；后端需同时运行在 `127.0.0.1:8000`。

```bash
# 1) 启动后端（先决条件）
cd backend
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000

# 2) 安装前端依赖
cd frontend
npm install

# 3) 启动前端开发服务器
npm run dev
# 买家端：      http://localhost:5173/
# 卖家后台：    http://localhost:5173/seller/login

# 4) 生产构建与本地预览
npm run build
npm run preview
```

> ⚠️ **必须用 `localhost`，不要用 `127.0.0.1`。** Vite 8 默认只监听 IPv6 的 `::1`，
> 实测 `http://127.0.0.1:5173` 会连接被拒（`Connection refused`），`localhost` 才通。
>
> 📱 **想在手机上测买家端 H5**：用 `npm run dev -- --host` 启动，Vite 会额外打印一个局域网地址
> （形如 `http://192.168.x.x:5173`），手机连同一 WiFi 即可访问。
> 注意该模式会把开发服务器暴露到局域网，演示结束记得改回默认启动方式。

**默认卖家账号：** 用户名 `seller`，密码 `seller123`。

## 7. 前后端对接约定

| 项目 | 约定 |
|---|---|
| 接口前缀 | `/api`，开发期经 Vite 代理到 `http://127.0.0.1:8000` |
| 静态图片 | 后端返回 `image_url` 形如 `/uploads/xxx.jpg`，前端用 `:src="product.image_url"` 直接引用（同样走代理） |
| 鉴权头 | `Authorization: Bearer <token>`，仅卖家接口需要 |
| 错误结构 | `{"error": {"code", "message"}}`，前端统一取 `message` 做提示 |
| 分页 | 请求 `page` / `page_size`，响应含 `items` / `total` / `page` / `page_size` |
| 时间 | 后端返回本地时间字符串 `YYYY-MM-DD HH:MM:SS`，前端直接展示，不做时区换算 |
| 金额 | 后端返回数值型元（2 位小数），前端展示时统一补 `¥` 前缀 |
| CSV 导出 | `GET .../intents/export` 返回文件流，前端以 `responseType: 'blob'` 处理并触发下载 |
| 中文文案 | 状态标签与提示语一律取自后端 `status_label` / `result_label` / `message` |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 令牌存 `localStorage` 被 XSS 窃取 | 后台被冒用 | 全站禁用 `v-html`；后端已做输入校验；令牌设有效期（`SHOP_TOKEN_TTL_SECONDS`） |
| 口令码存 `sessionStorage`，用户关闭标签页丢失 | 买家无法查询意向 | 提交成功页提供复制按钮与强提示；页面明确告知「丢失无法找回」（FR-050） |
| 浏览器兼容性（NFR-008） | 旧浏览器白屏 | Vite 默认目标为支持 ESM 的现代浏览器；演示前在 Chrome / Edge 双核验证 |
| 后端未启动时前端报错 | 演示中断 | 请求封装捕获网络错误，统一提示「无法连接服务器，请确认后端已启动」 |
| 买家端与后台组件库混用导致样式冲突 | 视觉不统一 | 买家端不使用 Element Plus，样式隔离在 `BuyerLayout` 内；后台统一走 Element Plus 主题变量 |
| 商品图片尺寸不一导致布局跳动 | 观感差 | 图片容器固定宽高比 + `object-fit: cover` |
| 口令码展示页被截图/截图后丢失 | 买家无法认领 | 页面强提示 + 复制按钮 + 建议截图保存的辅助说明 |

## 9. 结论

综合本机环境、双端形态差异、团队协作成本与课程交付节奏，前端采用 **Vue 3 + Vite + Vue Router + Pinia** 组合，卖家后台引入 **Element Plus** 承载表格与表单，买家端手写移动优先的响应式 CSS；通过 **Vite Dev Server 代理**统一 `/api` 与 `/uploads` 请求，实现开发与生产环境前端代码零差异。

该组合在本机零额外安装成本、双端可共用一套工程、组件覆盖后台高频场景，是当前项目条件下的合理选择。详细页面结构与交互设计见 `05-页面原型设计.md`。
