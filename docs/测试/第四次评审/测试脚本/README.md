## 二、怎么跑

### 1. 起后端（干净数据目录）

```bash
cd backend-java
mvn -s <你的 settings.xml> -Dmaven.test.skip=true package

# 干净数据目录，避免历史数据干扰
SHOP_DATA_DIR=./data-c java -jar target/shop-backend-1.0.0.jar --server.port=8000
```

### 2. 跑测试

```bash
python 测试脚本/01-全链路功能测试.py
```

### 3. 看结果

- 控制台逐条打印 `PASS / FAIL`
- 结尾汇总 `X 条，通过 Y，失败 Z`，并列出失败清单
- 证据写到 `测试脚本/证据/challengeC-full-<时间戳>.json`

## 四、脚本结构

```python
# 公共封装
api(method, path, body, token)     # 发请求，自动记录「方法/路径/请求体/是否带 token」
case(cid, module, title, expected, status, raw, ok)   # 登记一条用例
obj(raw, *keys)                    # 从响应里取对象
ec(raw) / em(raw)                  # 取错误码 / 错误信息

# 业务辅助
new_customer(tag)                  # 注册并登录一个客户
new_order(qty)                     # 加购 + 下单，返回订单号
pay(order, result)                 # 发起支付，result = SUCCESS / FAILED
db_stock(pid)                      # 直接查库拿 product.stock
```

**为什么这样组织**：用例只写「调一次接口 + 一次断言」，
公共逻辑（建号、下单、支付）抽成辅助函数，保证 63 条读起来不啰嗦。

## 七、断言语义提醒（避免误判）

| 现象 | 说明 |
| --- | --- |
| 交易完成后「可售库存」不变 | **正常**。下单时已占用，完成时库存实减、占用释放（C02 查库验证 stock 减 2） |
| 发货 `carrier` 传中文 → 422 | **正常**。必须是 `SF / JD / ZTO / YTO / YD / EMS / OTHER` |
| 不传 `address_id` 也能下单 | **正常**（FR-048 自动带出默认地址） |
| 已支付订单商家可取消 | **正常**（FR-044 需退款） |
