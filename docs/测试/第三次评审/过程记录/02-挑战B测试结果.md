## 四、⚠️ 发现的问题

### 问题 1：BUG-002 回归 —— 商品搜索 LIKE 通配符未转义（**新缺陷**）

**上一轮已修复的 BUG-002，在挑战B 重写 `ProductService` 时丢了。**

```java
// 当前代码（ProductService L130~132、L404~406）
where.append(" AND p.name LIKE ?");
params.add("%" + keyword.trim() + "%");     // ← 没有 ESCAPE，也没有转义
```

对比：`Utils.likePattern()` **方法还在**，但这里没用它；上一轮的写法是：

```java
where.append(" AND p.name LIKE ? ESCAPE '\\'");
params.add(Utils.likePattern(keyword.trim()));
```

**实测证据**：

| 请求 | 期望 | 实际 |
|---|---|:---:|
| `GET /api/products?keyword=%` | 0 条 | **10 条（全部）** ❌ |
| `GET /api/products?keyword=_` | 0 条 | **10 条（全部）** ❌ |
| `GET /api/products?keyword=商品` | 正常命中 | 10 条 ✅ |

> **严重度：高**。用户搜 `%` 或 `_` 会把全部商品搜出来，搜索结果失真。

### 问题 2：红项 1 未修 —— 卖家密码前后端仍不一致

复测 13 条，**5 条不一致仍在**（`abcdefgh`、`12345678`、`abcd1234`、`ABCD1234`、`密码密码1234`）。

`validateSellerPassword` 仍只查长度 8~128，**没有调用 `passwordClassCount`**。

### 问题 3：红项 2 未修 —— 手机号前后端仍不一致

复测 18 条，**10 条不一致仍在**：3 个座机、2 个本地号、带连字符/空格/括号、`+86`、`86` 前缀。

前端 `PHONE_RE` 仍只认 11 位手机号；后端仍接受手机/座机/本地号三类。

### 问题 4~6：遗留（见 `01-挑战B用例影响清单.md` 第五节）

| # | 问题 | 严重度 |
|:---:|---|:---:|

| 5 | `buy_intent` / `queue_item` / `trade_record` 三表 + 三个 Service 残留 | 低 |
| 6 | `FROZEN` 仍在枚举 `VISIBLE` 中，但公开列表已过滤 | 低 |

## 六、结论

1. **挑战B 新功能实现质量好**：收藏、购物车、多件下单、转收藏、订单 5 态、双向取消、库存占用/回补/扣减、游客会话、订单查询台账——**56 条新功能用例全部通过**。
2. **库存模型三条链路（下单占用 / 取消回补 / 完成扣减）实测正确**，这是挑战B 最核心的变更。
3. **但有一个回归**：`BUG-002`（LIKE 通配符）在重写 `ProductService` 时丢失，**搜索结果可以被 `%` 或 `_` 打穿**。
4. **两个老红项两周未修**（卖家密码、手机号），15 条不一致一条没少。
5. 另有 3 个遗留问题（死接口、死表、枚举不一致）。
