> 用途：自动化脚本跑完 108 条后，**用浏览器手工再走一遍核心流程**，确认「脚本能过」和「人能用」是同一回事
> 预计耗时：**20 ~ 25 分钟**
> 测试人：________　执行日期：________
> 被测版本：`main` = `bc01eaf`

---

## 〇、开始前

### 启动后端

```bash
cd backend-java
mvn -s <你的 settings.xml> -Dmaven.test.skip=true package
SHOP_DATA_DIR=./data java -jar target/shop-backend-1.0.0.jar --server.port=8000
```

**建议用干净数据目录**，否则种子数据里的商品可能已被改价/下架，影响判断。

### 启动前端

```bash
cd frontend
npm install
npm run dev
```

### 账号

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 卖家 | `seller` | `seller123` |
| 客户 | 自己注册 | 需 ≥8 位且 3 类字符，如 `Pass1234!` |

> ⚠️ 如果之前跑过自动化脚本，卖家密码可能已被改成 `Seller123!` 或 `Abcd1234`；
> 都登不上就删掉数据目录重启。

## 一、购物车（6 项）

| # | 操作 | 预期 |
| ---: | --- | --- |
| M1 | 未登录，商品详情页点「加入购物车」 | **允许**加入（游客购物车），提示成功 |
| M2 | 刷新页面，再看购物车 | 商品仍在（说明存在后端，不是本地缓存） |
| M3 | 购物车数量改成 `0` | 前端截断为 1，或提示不能为 0 |
| M4 | 购物车数量改成 `100` | 前端截断为 99，或提示不能超过 99 |
| M5 | 购物车数量改成 `999` 后点保存 | 被拦下，不提交给后端 |
| M6 | 购物车达到 50 种商品时再加第 51 种 | 提示「已达上限 50 件」 |

## 二、收藏（4 项）

| # | 操作 | 预期 |
| ---: | --- | --- |
| M7 | 商品详情页点「收藏」 | 收藏成功，导航栏收藏数 +1 |
| M8 | 再点一次收藏 | 提示「该商品已在收藏中」 |
| M9 | 去收藏页，取消收藏 | 列表移除，收藏数 -1 |
| M10 | 收藏页翻页（超过 100 条时） | **不报 422**，能翻到下一批 |

> M10 是上一轮修掉的问题（收藏分页 `page_size` 超过上限导致 422），批量收藏 100 条以上才能触发。

## 三、下单（5 项）

| # | 操作 | 预期 |
| ---: | --- | --- |
| M11 | 购物车勾选**一件**商品下单 | 跳转订单成功，购物车对应条目消失 |
| M12 | 购物车勾选**多件**商品下单 | 生成**一个**订单，含多个订单项 |
| M13 | 下单后看订单金额 | 等于各商品「单价 × 数量」之和 |
| M14 | 未登录点「去结算」 | 跳登录页（不能直接下单） |
| M15 | 购物车某商品库存不足时下单 | 弹提示并**标红具体商品**，其余可下单 |

> M15 对应后端返回的 `shortages` 明细，是挑战B 新增的逐项提示能力。

## 四、订单流转（5 项）

| # | 操作 | 预期 |
| ---: | --- | --- |
| M16 | 客户下单后，看订单详情 | 状态为「客户下单」，**客户端没有推进按钮** |

| M18 | 卖家依次点「备货完成」→「开始发货」→「交易完成」 | 状态依次推进，**不能跳步** |

## 五、双向取消（4 项）

| # | 操作 | 预期 |
| ---: | --- | --- |
| M21 | 客户在「备货完成」状态点取消 | **可以取消**（发货前） |
| M22 | 卖家「开始发货」后，客户再点取消 | **按钮消失或提示不可取消** |
| M23 | 同上订单，卖家点取消 | **可以取消**（完成前） |
| M24 | 取消后回商品详情页看库存 | **库存已回补**（比下单前多回来对应数量） |

> M24 是库存模型最关键的手工验证点：**下单占用 → 取消回补**。建议记下取消前后的可售数量对比。
