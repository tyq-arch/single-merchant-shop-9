## 一、版本说明（原文摘要）

> 本版为挑战 B 确认稿。经需求评审确认，**挑战 B 全面落地，取代挑战 A 的「意向 → 排队 → 先到先得 → 冻结 → 成交扣库存」模型**。
>
> 挑战 B 升级核心：
> - **B.1 订单升级**：从「提交购买意向排队」升级为「购物车选件下单 + 完整订单生命周期（5 态 + 双向取消）」；
> - **B.2 商品预选升级**：新增**收藏**、**购物车**、购物车**多件下单**、购物车**多件转收藏**。
>
> 由此，客户购买路径变为「浏览/搜索 → 加购/收藏 → 从购物车选单件或多件下单 → 订单 5 态流转」；
> 库存改为**下单占用 → 取消回补 → 完成扣减**。

## 二、新增 / 变更的需求条目

### 2.1 功能需求（FR）

| 编号 | 名称 | 变更 | 要点 |
| --- | --- | :---: | --- |
| FR-021 | 调整/移除购物车 | **增** | 调数量或移除购物车项，修改即时生效 |
| FR-022 | 预选暂存与下单登录 | **改** | 未登录可**临时**收藏/加购；**登录后自动合并** |
| FR-023 | 购物车多选下单 | **增** | 从购物车选单件或多件一次性下单 |
| FR-024 | 购物车多选转收藏 | **增** | 多选转收藏，完成后原购物车项移除 |
| FR-025 | 生成订单 | **增** | 下单生成订单，初始态「客户下单」，含多订单项 |
| FR-026 | 订单状态推进 | **增** | 客户下单 → 商家确认 → 备货完成 → 开始发货 → 交易完成 |
| FR-027 | 订单只读 | **增** | 客户仅可查看订单状态，不可推进 |
| FR-028 | 客户取消订单 | **增** | 「开始发货」前可取消，置已取消并回补库存 |
| FR-029 | 商家取消订单 | **增** | 「交易完成」前可取消，置已取消并回补库存 |
| FR-030 | 订单查询/历史 | **改** | 记录含订单号、商品清单、金额、状态 |
| FR-031 | 商家订单管理 | **增** | 订单列表 / 按状态筛选 / 推进 / 取消 |
| FR-032 | 商家客户台账 | **改** | 查看注册客户，固定字段：用户名/电话/默认交易地点 |
| FR-033 | 商家购买/订单历史 | **改** | 查看客户订单历史 |
| FR-034~FR-038 | 卖家登录 / 无注册 / 修改密码 / 操作日志 / 终端与过程 | **改** | 卖家侧沿用挑战A 并补充订单相关 |

### 2.2 非功能需求（NFR）

| 编号 | 名称 | 要点 |
| --- | --- | --- |
| NFR-003 | 账号安全 | 客户/卖家密码哈希存储；**密码规则：≥8 位 + 强度要求** |
| **NFR-005** | **库存一致性** | **下单占用、取消回补、完成扣减需事务保证一致，防止超卖/泄漏** |
| **NFR-006** | **订单一致性** | **订单状态单向状态机，并发操作需事务 + 行锁，避免错乱与重复取消** |
| NFR-010 | 审计 | 卖家关键操作可追溯，订单/库存变更完整记录 |

## 三、对测试的重点提示

| 需求 | 测试要点 |
| --- | --- |
| FR-022 | 游客可加购/收藏，但**下单必须登录**；登录后游客数据要**自动合并** |
| FR-023 / FR-025 | 多件一起下单；缺货时要**逐项提示**（对应 TBD-04 的 `shortages` 明细） |
| FR-024 | 转收藏后原购物车项**必须移除** |
| FR-026 / FR-027 | 状态只能**按序推进**，客户不可推进 |
| FR-028 / FR-029 | 取消边界：客户「发货前」、商家「完成前」；取消后**必须回补库存** |
| NFR-005 | 下单占用、取消回补、完成扣减三条链路；**并发下不能超卖** |
| NFR-006 | 订单状态单向不可逆；**重复取消必须被拒** |
| TBD-11 | 购物车 50 种、收藏 200 条、单品 1~99 的上限 |
