| 控制台完整输出 | `_runtime/run1.txt`、`_runtime/run2.txt` |

### 怎么复核（三种方式）

1. **看证据**：打开工作簿「原始响应证据」页，任选一条，看请求体和响应体是否对得上
2. **自己重跑**：

   ```bash
   cd backend-java
   mvn -s <settings.xml> "-Dmaven.test.skip=true" package
   SHOP_DATA_DIR=<空目录> java -jar target/shop-backend-1.0.0.jar --server.port=8000
   python 测试脚本/01-挑战A功能测试.py
   python 测试脚本/02-挑战A边界对抗测试.py
   ```

3. **手工单条**：用 Swagger UI（`http://127.0.0.1:8000/docs`）发同样的请求体

### 为什么这些结果可信

| 原则 | 说明 |
|---|---|
| 黑盒 | 只通过 HTTP 接口观察，不 mock、不注入、不读内部状态 |
| 真实进程 | 真 Spring Boot 进程 + 真 SQLite 落库，走完整 路由→鉴权→校验→业务→持久化 链路 |
| **预期来自需求** | 断言值取自 `C-xx / FR-xxx / NFR-xxx`，**不是先读代码再抄行为** |
| 可复核 | 每条留下原始响应，第三方可重放 |
| 可重复 | 每轮清空数据库 + 数据带时间戳后缀，两次运行结果一致 |

> **关键一句**：如果先读代码、再把代码行为写成"预期"，测试就退化成复述实现，永远 100% 通过、毫无价值。
