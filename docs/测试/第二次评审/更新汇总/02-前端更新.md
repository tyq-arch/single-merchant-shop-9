## 二、买家端联系电话改为 11 位手机号校验

### 2.1 新增统一校验工具 `src/utils/validate.js`

```js
/** 中国大陆手机号：11 位数字，1 开头，第二位 3-9 */
export const PHONE_RE = /^1[3-9]\d{9}$/

/** 手机号固定 11 位 */
export const PHONE_LENGTH = 11

export function validatePhone(value) {
  const phone = String(value ?? '').trim()

  if (!phone) return '请输入联系电话'
  if (!/^\d+$/.test(phone)) return '联系电话只能输入数字'
  if (phone.length !== PHONE_LENGTH) {
    return `请输入 ${PHONE_LENGTH} 位手机号（当前 ${phone.length} 位）`
  }
  if (!PHONE_RE.test(phone)) return '手机号格式不正确，请检查后重试'

  return ''
}
```

**设计意图**（原文注释）：提交意向（`IntentFormView`）和修改联系方式（`IntentDetailView`）都要校验手机号，**规则只写一份**，避免两处提示文案或正则不一致。

### 2.2 两个视图的改动

| 改动点 | `IntentFormView.vue`（提交意向） | `IntentDetailView.vue`（修改联系方式） |
| --- | --- | --- |
| 删除旧正则 | 删掉 `const PHONE_RE = /^[0-9+\-\s]{5,20}$/` | 同 |
| 引入工具 | `import { PHONE_LENGTH, validatePhone } from '@/utils/validate'` | 同 |
| 输入框限制 | 加 `:maxlength="PHONE_LENGTH"`、`inputmode="numeric"` | 同 |
| 即时校验 | 新增 `@blur="validatePhoneField"`，失焦即提示 | 同 |
| 占位提示 | 改为「请输入 11 位手机号」 | 同 |
| 注释 | 原「校验规则与后端 `BuyerIntentCreateRequest` 保持一致」**被删除**，改为「规则见 `utils/validate.js`」 | — |
| 额外防御 | — | 号码**未改动时不触发校验**（`phone === order.value?.buyer_phone` 时跳过），避免历史数据编辑时误报 |

### 2.3 校验规则总结

| 规则 | 说明 |
| --- | --- |
| 必填 | 空值提示「请输入联系电话」 |
| 纯数字 | 含非数字字符提示「联系电话只能输入数字」 |
| 固定 11 位 | 长度不符时提示当前位数 |
| 号码段 | 1 开头、第二位 3~9（`^1[3-9]\d{9}$`） |
| 交互 | 输入框限 11 位、数字键盘、失焦即时校验 |

## 三、事实性说明

1. **后端校验规则本周未改**。`backend/app/schemas.py` 中 `buyer_phone` 仍是
   `^[0-9+\-\s]{5,20}$`（5~20 位，允许 `+`、`-`、空格）+ `min_length=5, max_length=20`。
   即：**前端已按 11 位大陆手机号收紧，后端仍是宽松校验**。两层的规则当前不一致。

2. **原注释被删除**。`IntentFormView.vue` 里原本写着「校验规则与后端 `BuyerIntentCreateRequest` 保持一致」，
   本次改动把这句删掉并改为指向 `utils/validate.js`，说明改动者已知两层规则不再一致。

3. **界面层已挡住不合规输入**。输入框加了 `maxlength=11` 与 `inputmode="numeric"`，
   通过浏览器操作无法输入 `+`、`-`、空格或超过 11 位的号码。

4. **手册未覆盖 Node 版本要求**。项目依赖 `vite@8.3.3`，该版本要求 **Node ≥ 22**；
   本机曾用 Node v20.19.0 执行 `npm install` 报 `EBADENGINE`，需切换版本才能正常构建。
   建议在手册第 1.1 节补充显式的 Node 版本检查。
