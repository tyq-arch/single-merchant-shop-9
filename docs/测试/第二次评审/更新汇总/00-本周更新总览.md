## 三、三块主要更新

### 更新 1：需求文档升级为「挑战 A」版 —— 系统模式发生根本变化

原文开篇写明核心思路：

> 「看不用登录，买必须登录」、多商品并发、库存驱动售卖、口令码/自动递补作废、排队/冻结保留并改造。

| 维度 | 原基线 | 挑战 A |
| --- | --- | --- |
| 商品数量 | 同一时间仅一件在售 | **多商品可同时在售** |
| 买家身份 | 匿名，凭姓名电话 | **注册客户**（用户名/密码/电话/默认交易地点） |
| 下单门槛 | 无需登录 | **必须登录**（游客只能浏览、搜索） |
| 售卖凭据 | **口令码** | **口令码机制作废** |
| 库存 | 无 | **库存数量**，0 自动下架，成交扣 1，可补货 |
| 类别 | 无 | **2 级类别**，商品必挂小类 |
| 图片 | 最多 1 张主图 | **最多 9 张**，JPG/PNG，≤5MB，首图为主图 |
| 描述 | 纯文本 | **富媒体**（内嵌图文视频，仅本地上传） |
| 查找 | 仅浏览 | **浏览 + 搜索** |
| 撤销/修改意向 | 可改可撤 | **作废** |
| 自动递补 | 自动让下一位进入交易 | **作废**，改为卖家确认时同步选择 |
| 商品状态 | 3 态 | **5 态**：草稿 / 在售 / 冻结 / 售罄下架 / 手动下架 |

文档第 12 章给出了 **`C-01 ~ C-30`** 共 30 条变更对照（增 11、改 10、废 2、保留 2、确认 4、待确认 1）。

> 详见《01-需求更新.md》，原文见 `../附件/需求规格说明书-挑战A升级版（原文）.md`

## 三之二、本周更新的测试结果速览

针对本周唯一的前端代码改动（11 位手机号校验）做了定向测试：

| 测试层面 | 用例数 | 结果 |
| --- | ---: | --- |
| 前端校验函数（`validatePhone`） | 16 | **16 例全部符合规则设计，无缺陷** |
| 后端接口（`POST /api/buyer/intents`） | 16 | 仍按旧宽松规则放行 |
| 前后端一致性对照 | 16 | **一致 7 项，不一致 9 项** |

**结论**：前端实现正确；后端未同步，同一批号码（`+8613800000000`、`12345`、`23800000000` 等）前端拒绝、后端接受。正常界面操作不受影响，但接口层可绕过。

> 详见`../测试材料/02-测试报告.md`；手动验证步骤见 `../测试材料/03-手动测试指南.md`。
