### 发现的 7 项工程问题

1. 团队自己的集成测试编译不过（`queueHead` 重复定义），`mvn test` 必然失败 ← **最严重**
2. 需求文档 `C-29` / `C-30` 各出现两次
3. 商品状态少一个「草稿」（需求 5 态，代码 4 态）
4. 卖家种子密码 `seller123` 改密后无法回退
5. `schema.sql` 商品 `status` 缺 CHECK 约束
6. 前端密码规则落后于后端（前端 ≥6 位，后端 ≥8 位 + 3 类）
7. 用例 `K02` 表述错误

> 另有**问题 0**（前后端手机号规则不一致）记为观察项 **OBS-014**，不计入这 7 项。

## 三、两轮的关系

挑战A 是一次**架构级重写**，不是增量迭代：

- 前端按挑战A 需求**完全重写**（19 个视图，口令码页面全删）
- **新增整套 Java 后端**，旧 Python 后端前端已不再调用
- 商品状态机、意向状态机、口令码机制均有变更

因此第二轮的用例是**按新需求重写**的，不是在第一轮 117 条上改造。
两轮的用例编号体系不同，**不要交叉引用**。
