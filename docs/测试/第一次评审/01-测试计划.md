## 1 测试目的

明确测试范围、策略、环境、组织分工、进度安排与准入准出标准，作为测试岗开展功能测试、
缺陷记录与验收校验的统一依据，同时作为阶段性评审与项目验收时测试工作的说明材料。

## 2 测试对象与范围

**被测对象**：single-merchant-shop-9 仓库当前主分支的前后端完整实现。

- 后端：Python 3.12 + FastAPI + Uvicorn + SQLite（WAL 模式），24 个接口；
- 前端：Vue 3 + Vite + Vue Router + Pinia + Element Plus，12 条路由（买家端 5 页 + 卖家后台 7 页）；
- 数据层：6 张业务表，含唯一在售约束与金额 CHECK 约束。

**覆盖范围**

| 序号 | 测试类型 | 覆盖内容 |
| --- | --- | --- |
| 1 | 接口功能测试 | 24 个 HTTP 接口的正常流与异常流 |
| 2 | 业务流程测试 | 浏览 → 提交意向 → 排队 → 进入交易 → 标记结果的端到端流程 |
| 3 | 状态机测试 | 商品 3 态、意向 7 态、口令码 2 态的合法与非法迁移 |
| 4 | 边界与异常测试 | 字段长度、金额边界、分页边界、非法枚举、非法 JSON、超长参数 |
| 5 | 并发一致性测试 | 多线程并发提交意向、并发进入交易 |
| 6 | 安全性测试 | 鉴权覆盖、越权访问、SQL 注入、路径穿越、XSS 存储 |
| 7 | 隐私保护测试 | 买家电话脱敏规则 |
| 8 | 前端可用性测试 | 12 条路由可访问性、模块编译、前后端代理联调 |
| 9 | 文档一致性核对 | 需求 / 接口 / 页面文档之间的一致性 |

**不覆盖范围**

- 专业性能压测与长时间稳定性测试（NFR-007 可用性 ≥99% 无法在课程单机环境验证）；
- 多浏览器、多终端兼容性矩阵测试；
- HTTPS、CSRF 等部署层安全项（课程环境为本地 HTTP 明文部署）；
- 需求文档中列为 TBD 且尚未实现的功能（TBD-01 ~ TBD-14）。

## 3 测试策略

| 层次 | 测试类型 | 执行方式 | 责任人 |
| --- | --- | --- | --- |
| 第 1 层 | 开发自测（单元/接口） | 仓库自带 pytest 用例 | 郭子涵（后端） |
| 第 2 层 | 黑盒功能测试 | 自动化套件对运行中的服务发起真实请求 | 缪茂锦（测试） |
| 第 3 层 | 前端功能与联调测试 | 浏览器人工走查 + HTTP 层可用性校验 | 吴顺宝 / 缪茂锦 |
| 第 4 层 | 验收测试与合规检查 | 依据验收清单与合规表逐项核对 | 缪茂锦（测试） |

**测试方法**：黑盒测试为主、等价类划分与边界值分析、状态迁移测试、场景法、
并发测试（20 线程）、错误推测法（结合代码走查针对金额换算、LIKE 通配符、鉴权缺失等高危点）。

## 6 准入与准出标准

**准入**：被测版本已完成开发自测且 pytest 全部通过；前后端均可正常启动；
需求/数据库/接口/页面设计文档已提交；测试环境就绪、数据库可重建。

**准出**：用例执行率 100%，无因环境问题被阻塞的用例；无「高」级别未修复缺陷；
「中」级别缺陷已修复并回归通过或在报告中说明影响与规避方式；
功能验收通过率不低于 95%；测试报告完成且结论明确。
