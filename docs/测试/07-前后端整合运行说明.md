# 前后端整合运行说明

> 编写人：缪茂锦（测试岗）
> 用途：把仓库中的前端与后端在本地整合启动、打通联调，供开发自测、测试执行与评审演示使用。
> 本说明中的所有步骤与端口均已在本机实际验证通过。

## 一、环境要求

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| Python | **3.10 及以上**（实测 3.12.10） | 后端 FastAPI 运行环境 |
| Node.js | **≥ 22**（实测 v24.21.0） | ⚠️ 前端 `vite@8.3.3`、`@vueuse` 等依赖声明 `node >= 22`；在 Node v20 下 `npm install` 会报 `EBADENGINE` 告警，建议直接使用 Node 22/24 |
| 数据库 | 无需单独安装 | 后端使用 Python 内置 SQLite，首次启动自动建库建表 |
| 浏览器 | Chrome / Edge 等现代浏览器 | 前端为 Vue 3 单页应用 |

## 三、启动步骤

### 3.1 启动后端（终端 1）

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

也可以直接用自带脚本（等价）：

```bash
cd backend
python run.py
```

启动成功的标志：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

首次启动时 `init_db()` 会自动执行，完成两件事：

1. 按 `app/schema.sql` 建表（自动创建 `backend/data/` 目录与 `shop.db`）；
2. 写入唯一固定卖家账号：**用户名 `seller`，密码 `seller123`**。

**验证后端**

```bash
# 服务信息
curl http://127.0.0.1:8000/

# 当前商品（无商品时返回 state=NONE）
curl http://127.0.0.1:8000/api/products/current

# Swagger 接口文档
# 浏览器打开 http://127.0.0.1:8000/docs
```

### 3.2 启动前端（终端 2）

```bash
cd frontend
npm install
npm run dev
```

启动成功的标志：

```
  VITE v8.3.3  ready in 272 ms

  ➜  Local:   http://127.0.0.1:5173/
```

**打开浏览器访问** <http://127.0.0.1:5173/>

## 四、前后端如何打通（关键点）

前后端**不在同一个端口**，靠 Vite 的开发代理联通。`frontend/vite.config.js`：

```js
server: {
  port: 5173,
  proxy: {
    '/api':     { target: 'http://127.0.0.1:8000', changeOrigin: true },
    '/uploads': { target: 'http://127.0.0.1:8000', changeOrigin: true },
  },
}
```

因此：

- 前端代码里所有请求都写成相对路径（`baseURL: '/api'`），**不需要写 `http://127.0.0.1:8000`**；
- 浏览器访问 `http://127.0.0.1:5173/api/products/current` 时，请求会被 Vite 转发到后端的 `http://127.0.0.1:8000/api/products/current`；
- 商品主图同理：后端返回 `/uploads/xxx.png`，经同一代理取回图片。

**这样做的意义**：前端代码在开发环境与生产环境完全一致，部署时只需让后端同时托管 `dist` 静态文件或由 Nginx 统一转发 `/api`，无需修改任何前端源码。

**联调验证方法**：直接把浏览器的 `/api/products/current` 地址粘到地址栏（即 `http://127.0.0.1:5173/api/products/current`），若返回 JSON 而非 404，说明代理已打通。

## 六、推荐演示流程（评审时使用）

按下述顺序操作，可在一个屏幕内完整展示核心业务闭环：

1. **卖家登录** → 平台 `/seller/login`，用 `seller / seller123` 登录；
2. **发布商品** → `/seller/publish` 发布一件商品（名称、价格必填），发布后商品为「在售」；
3. **买家提交意向** → 打开 `/`，点「我要购买」，填姓名与电话提交，**记录口令码**；
4. **再提交一笔** → 用另一姓名/电话再提交一次，此时排队序号为 2；
5. **进入交易** → 回到卖家工作台，点「与队首进入交易」，商品自动变为「已冻结」，队列封口；
6. **标记交易失败** → 点「标记交易失败」，观察下一位买家**自动递补**进入交易，商品仍为「已冻结」；
7. **处置失败者** → 对失败买家点「重新排队」，系统放回队尾并生成**新口令码**；
8. **标记交易成功** → 对该买家点「标记交易成功」，商品自动下架并进入历史记录；
9. **查看历史** → `/seller/history` → 详情页可见商品快照、完整交易过程与脱敏后的买家信息。

演示要点：任何时刻买家都无法绕过口令码；队列严格按提交时间；卖家无法手动调整队列或挑选买家。

## 七、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 前端页面打开但提示「无法连接服务器，请确认后端已启动」 | 后端未启动或端口不是 8000 | 确认终端 1 的 uvicorn 正在运行，且端口为 8000 |
| 端口 8000 被占用（`error while attempting to bind on address`） | 已有后端实例在运行 | Windows：`netstat -ano \| findstr :8000` 找到 PID 后 `taskkill /PID <PID> /F`；或改用其他端口并同步修改 `vite.config.js` 的代理目标 |
| `npm install` 出现 `EBADENGINE ... required: { node: '>=22' }` | Node 版本过低 | 升级到 Node 22 或 24 后重新 `npm install` |
| 卖家登录提示「用户名或密码错误」 | 数据库是旧库或密码已被修改 | 删除 `backend/data/shop.db` 后重启后端，会重新建库并写入默认账号 |
| 买家查询口令码提示「口令码无效或已失效」 | 口令码已因交易成功/失败/下架/撤销而失效 | 属正常业务行为；口令码丢失无法找回，需重新提交意向 |
| 上传图片失败 | 格式不在 jpg/jpeg/png/gif/webp 内，或超过 5MB | 更换图片后重试 |

## 八、数据与环境变量配置

后端所有配置均可通过环境变量覆盖（见 `backend/app/config.py`），无需改代码：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SHOP_DATA_DIR` | `backend/data` | 数据目录 |
| `SHOP_DB_PATH` | `backend/data/shop.db` | SQLite 数据库路径 |
| `SHOP_UPLOAD_DIR` | `backend/data/uploads` | 上传图片目录 |
| `SHOP_SELLER_USERNAME` / `SHOP_SELLER_PASSWORD` | `seller` / `seller123` | 卖家账号 |
| `SHOP_SECRET_KEY` | `dev-secret-key-change-me` | 会话令牌签名密钥 |
| `SHOP_TOKEN_TTL_SECONDS` | `43200`（12 小时） | 令牌有效期 |
| `SHOP_COMMAND_CODE_TTL_DAYS` | `30` | 口令码有效期 |
| `SHOP_MAX_IMAGE_BYTES` | `5242880`（5MB） | 单张图片大小上限 |

> ⚠️ **部署提醒**：`SHOP_SECRET_KEY` 与 `SHOP_SELLER_PASSWORD` 的默认值仅供开发使用，正式部署前必须通过环境变量替换。此项已列入《上线合规检查表》，结论为「有条件通过」。

**重置测试数据**：停止后端 → 删除 `backend/data/` 目录 → 重新启动后端，即得到全新数据库与默认账号。
