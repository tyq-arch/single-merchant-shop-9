# 前端构建与部署手册

> 适用范围：在线购物系统（单卖家版）· **挑战A升级版**
> 前端技术栈：Vue 3 + Vite + Vue Router + Pinia + Element Plus
> 后端技术栈：Spring Boot 2.7.18（Java 8+，实测 JDK 26 可运行）+ SQLite
> 目标读者：需要从零拉取源码、本地运行或部署本系统的人员

---

## 1. 环境要求

### 1.1 软件版本

| 软件 | 最低要求 | 本项目实测版本 | 说明 |
|---|---|---|---|
| **Node.js** | `^20.19.0` 或 `>=22.12.0` | **v24.10.0** | 由 Vite 8 的 `engines` 字段决定，低于此版本 npm 会报错 |
| **npm** | 随 Node.js 安装 | **11.6.1** | 使用 npm 安装依赖 |
| **JDK** | 8+ | **26.0.1** | 运行 Spring Boot 后端；项目 `pom.xml` 声明 Java 8 |
| **Maven** | 3.6+ | **3.9.16** | 编译、打包、运行后端 |
| **Git** | 任意较新版本 | — | 获取源码使用 |
| **浏览器** | Chrome / Edge 最新版 | — | 需支持 ES2020 |

> ⚠️ **Node.js 版本是硬性条件。** Vite 8.3.3 的 `package.json` 中声明为
> `"engines": { "node": "^20.19.0 || >=22.12.0" }`，版本不足会导致安装或启动直接失败。

> ℹ️ 挑战A升级版的后端已由 Python/FastAPI 改为 **Java/Spring Boot**，
> 本地运行与部署都**不再需要 Python**。仓库中的 `backend/` 是 V1 旧实现，不适用于本版接口。

### 1.2 环境核对

在终端执行以下命令确认版本：

```bash
node -v      # 应输出 v20.19.0 以上，或 v22.12.0 以上
npm -v
java -version
mvn -v
git --version
```

### 1.3 网络与磁盘

- 首次 `npm install` 会安装 **7 个直接依赖、约 120 个传递依赖**，需可访问 npm registry。
- 首次 `mvn package` 会下载 Spring Boot 依赖，需可访问 Maven 仓库。
- 国内网络较慢时可切换镜像（可选）：

```bash
npm config set registry https://registry.npmmirror.com
```

- `node_modules` 约 200 MB，`target/` 约 40 MB，请预留磁盘空间。

## 4. 启动开发环境

### 4.1 启动顺序

**必须先启动后端，再启动前端。** 前端的开发代理指向 `127.0.0.1:8000`，后端未启动时页面能打开但所有接口都会失败。

```
终端 1：启动后端 (:8000)
        ↓
终端 2：启动前端 (:5173 或自动顺延端口)
```

### 4.2 启动后端

方式一（已打包）：

```bash
cd backend-java
java -jar target/shop-backend-1.0.0.jar
```

方式二（Maven 直接运行）：

```bash
cd backend-java
mvn spring-boot:run
```

启动成功的标志：

```
Tomcat started on port(s): 8000 (http)
Started ShopApplication in 2.5 seconds
```

验证：

- 服务信息：<http://127.0.0.1:8000/>
- **接口文档（Swagger UI）：<http://127.0.0.1:8000/docs>**
- 商品列表：<http://127.0.0.1:8000/api/products>

> ⚠️ `/docs` 只能通过 **8000 端口**访问。前端开发服务器只代理 `/api` 和 `/uploads`，
> 访问 `localhost:5173/docs` 会命中前端路由的兜底规则而跳转到买家首页。

> ℹ️ 在 JDK 26 上启动时可能出现 `restricted method` / `sun.misc.Unsafe`
> 之类的 **WARNING**，这是 Spring Boot 2.7 + 新版 JDK 的兼容提示，不影响运行。

### 4.3 启动前端

```bash
cd frontend
npm run dev
```

启动成功的标志：

```
VITE v8.3.3  ready in 517 ms
➜  Local:   http://localhost:5176/
```

**访问终端实际输出的地址。** 本项目开发机上 5173–5175 被代理软件占用，
Vite 自动顺延到了 **5176**。默认情况下（端口空闲）是 5173。

> ⚠️ **必须使用 `localhost`，不要使用 `127.0.0.1`。**
> 本项目实测 Vite 8 开发服务器监听在 IPv6 地址 `[::1]`，
> 访问 `http://127.0.0.1:5173` 会连接失败。
> 需要让局域网其他设备访问时，追加 `--host` 参数（`npm run dev -- --host`）。

### 4.4 端口冲突处理

若 5173 已被占用，Vite 会自动尝试下一个可用端口，以终端实际输出为准。也可显式指定：

```bash
npm run dev -- --port 5180
```

后端端口被占用时：

```bash
java -jar target/shop-backend-1.0.0.jar --server.port=8001
```

此时需同步修改 `frontend/vite.config.js` 中 `server.proxy` 的 `target`。

### 4.5 开发代理说明

[`frontend/vite.config.js`](../frontend/vite.config.js) 中配置了两条代理：

```js
server: {
  port: 5173,
  proxy: {
    '/api':     { target: 'http://127.0.0.1:8000', changeOrigin: true },
    '/uploads': { target: 'http://127.0.0.1:8000', changeOrigin: true },
  },
}
```

**作用**：浏览器请求的是同源的 `localhost:端口/api/...`，由 Vite 在背后转发到后端，
从而绕开浏览器的同源策略限制。

因此**业务代码中一律使用 `/api` 开头的相对路径**（见 `src/api/http.js` 的 `baseURL: '/api'`），
不写完整域名——这样开发环境与生产环境的业务代码零差异。

### 4.6 登录入口与默认账号

系统有**两个独立登录入口**，账号不互通：

| 角色 | 入口 | 地址 | 账号 |
|---|---|---|---|
| 卖家 | 卖家后台 | `http://localhost:5176/seller` | `seller` / `seller123` |
| 客户 | 买家端登录 | `http://localhost:5176/login` | 需自行注册 |

> ⚠️ **卖家账号只能在卖家后台登录。** 在买家端「客户登录」页输入 `seller / seller123`
> 会被后端按客户账号校验，返回「用户名或密码错误」。

客户注册地址：`http://localhost:5176/register`
（用户名、密码、**11 位大陆手机号**、默认交易地点）。

### 4.7 启动验证清单

| 检查项 | 验证方式 | 预期结果 |
|---|---|---|
| 后端存活 | 浏览器打开 `http://127.0.0.1:8000/docs` | 显示 Swagger 页面 |
| 前端存活 | 浏览器打开终端输出的前端地址 | 显示买家端商品列表 |
| **代理链路** | `curl http://localhost:<端口>/api/products` | 返回 JSON，而非 HTML |
| 卖家登录 | 打开 `/seller`，账号 `seller` / `seller123` | 进入工作台 |
| 客户注册 | 打开 `/register`，填写 11 位手机号 | 注册成功后跳转登录页 |

### 5.1 买家端（游客可浏览，购买需登录）

| 路由 | 页面 | 说明 |

### 5.3 首次使用建议流程

1. 卖家登录 → 类别管理，创建**一级类别**，再在其下创建**二级类别**
2. 发布商品：选择二级类别、填写名称/价格/库存、上传图片与描述
3. 买家注册客户 → 登录 → 打开商品 → 我要购买
4. 卖家在意向队列中「与队首进入交易」→ 线下交易 → 标记成功/失败

> 商品**必须归属二级类别**；库存为 0 时商品自动售罄下架，补货到大于 0 自动恢复在售。

## 6. 生产构建

### 6.1 构建前：清理旧产物（重要）

**本项目实测：`npm run build` 不会清空 `dist/` 中上一次构建的产物**，
多次构建后旧哈希文件会持续累积，导致目录越来越大，且容易误部署过期文件。

因此**每次构建前先删除 `dist/`**：

```bash
cd frontend

# Windows (Git Bash) / macOS / Linux
rm -rf dist

# Windows CMD 可用
rmdir /s /q dist
```

### 6.2 执行构建

```bash
npm run build
```

构建成功的标志（最后一行）：

```
✓ built in 7.71s
```

> 首次构建约 8 秒，之后增量构建约 1 秒。

### 6.3 产物位置与结构

```
frontend/dist/
├── index.html          唯一入口 HTML
└── assets/             打包后的 JS / CSS / 字体等静态资源
    ├── index-<hash>.js         主包
    ├── ProductListView-<hash>.js 各页面按路由懒加载切分
    ├── ...
    └── index-<hash>.css
```

文件名带内容哈希，内容不变则文件名不变，可安全地配置长期缓存。

### 6.4 关于构建体积警告

构建过程中可能出现：

```
(!) Some chunks are larger than 500 kB after minification.
```

这是 **Vite 对单个 chunk 超过 500 KB 的提示，不是构建失败**。
本项目主包约 850 KB（gzip 后约 268 KB），原因是 **Element Plus 采用全量引入**
（见 `src/main.js` 中的 `app.use(ElementPlus)`）。

后续优化方向：改为 Element Plus 按需引入，可显著降低主包体积。

## 8. 部署

### 8.1 上传前端静态文件

将 `dist/` 目录下的**全部内容**上传到静态服务器（Nginx / Apache / 对象存储均可）的站点根目录。

构建产物是纯静态文件，**不需要 Node.js 运行环境**。

### 8.2 Nginx 配置示例

```nginx
server {
    listen       80;
    server_name  your-domain.com;

    # 站点根目录指向 dist 上传后的位置
    root  /var/www/single-merchant-shop;
    index index.html;

    # 【必须】history 路由兜底
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 【必须】接口反向代理
    location /api/ {
        proxy_pass         http://127.0.0.1:8000;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
    }

    # 【必须】上传图片/视频访问
    location /uploads/ {
        proxy_pass http://127.0.0.1:8000;
    }

    # 带哈希的静态资源可长期缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### 8.3 为什么必须配置 `try_files`

前端路由使用 **history 模式**（`src/router/index.js` 中的 `createWebHistory()`），
URL 中没有 `#`，例如 `/seller/publish`。

但服务器上**并不存在**名为 `/seller/publish` 的文件。若不做兜底：

- 用户从首页点击跳转 → 正常（由前端路由处理，不发请求）
- 用户**直接访问或刷新** `/seller/publish` → 服务器返回 **404**

`try_files $uri $uri/ /index.html;` 的作用是：找不到对应文件时统一返回 `index.html`，
交给前端路由解析。

> 这也是开发环境感知不到该问题的原因——Vite 开发服务器与 `vite preview` 已内置此兜底逻辑。

### 8.4 后端部署

生产环境启动后端：

```bash
cd backend-java
java -jar shop-backend-1.0.0.jar --server.port=8000
```

注意：

- 生产环境**必须修改默认密钥与卖家密码**（见 8.5）。
- `backend-java/data/` 是运行时数据目录，请确保运行用户有读写权限，并纳入备份。
- 需要服务器安装 **JDK**（8 及以上），不需要 Maven 与 Node.js。

### 8.5 生产环境变量

后端支持以下环境变量（也可用 `--shop.xxx=` 命令行参数）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SHOP_DATA_DIR` | `backend-java/data` | 数据目录 |
| `SHOP_DB_PATH` | `<data>/shop-v2.db` | SQLite 文件路径 |
| `SHOP_UPLOAD_DIR` | `<data>/uploads` | 上传文件目录 |
| `SHOP_SELLER_USERNAME` | `seller` | 卖家账号（仅首次建库时写入） |
| `SHOP_SELLER_PASSWORD` | `seller123` | 卖家初始密码（仅首次建库时写入） |
| `SHOP_SECRET_KEY` | `dev-secret-key-change-me` | 令牌签名密钥，**生产必须修改** |
| `SHOP_TOKEN_TTL_SECONDS` | `43200`（12 小时） | 登录令牌有效期 |
| `SHOP_MAX_IMAGE_BYTES` | `5242880`（5MB） | 商品图片大小上限 |
| `SHOP_MAX_MEDIA_BYTES` | `52428800`（50MB） | 富媒体视频大小上限 |

Linux 示例：

```bash
export SHOP_DATA_DIR=/var/lib/shop
export SHOP_SECRET_KEY='请替换为随机长字符串'
export SHOP_SELLER_PASSWORD='请替换为强密码'
java -jar /opt/shop/backend-java/shop-backend-1.0.0.jar --server.port=8000
```

> ⚠️ `SHOP_SELLER_USERNAME` / `SHOP_SELLER_PASSWORD` 只在数据库首次初始化时生效。
> 数据库已存在时修改密码请使用后台「修改密码」功能。

### 8.6 systemd 示例（可选）

```ini
[Unit]
Description=Single Merchant Shop Backend
After=network.target

[Service]
User=shop
WorkingDirectory=/opt/shop/backend-java
Environment=SHOP_DATA_DIR=/var/lib/shop
Environment=SHOP_SECRET_KEY=replace-with-a-long-random-string
ExecStart=/usr/bin/java -jar /opt/shop/backend-java/shop-backend-1.0.0.jar --server.port=8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

## 9. 常见问题排查

| # | 现象 | 原因 | 处理方法 |
|---|---|---|---|
| 1 | `npm install` 报 engine 版本不满足 | Node.js 版本过低 | 升级到 `20.19+` 或 `22.12+` |
| 2 | `127.0.0.1:<端口>` 打不开，`localhost` 正常 | Vite 监听在 IPv6 `::1` | 统一使用 `localhost` |
| 3 | 5173 打不开，终端显示 5174/5175/5176 | 端口被其他程序占用，Vite 自动顺延 | 以终端实际输出的端口为准 |
| 4 | 页面能打开，但所有接口失败 | 后端未启动 | 先执行 `cd backend-java && java -jar target/...jar` |
| 5 | 接口返回 HTML 而非 JSON | 请求走了前端路由兜底，未命中代理 | 检查路径是否以 `/api` 开头 |
| 6 | `localhost:<端口>/docs` 打不开 | 代理只覆盖 `/api`、`/uploads` | 文档请访问 `127.0.0.1:8000/docs` |
| 7 | **卖家账号登录失败** | 进错登录页：买家端「客户登录」不接受卖家账号 | 使用 `/seller` 进入卖家后台登录 |
| 8 | **部署后刷新子路径 404** | 缺少 history 路由兜底 | Nginx 配置 `try_files ... /index.html` |
| 9 | 部署后商品图片/视频不显示 | `/uploads` 未反向代理 | 增加 `location /uploads/` 转发 |
| 10 | `dist/` 越来越大、存在多个 `index-*.js` | 旧产物未被清空 | **构建前先 `rm -rf dist`** |
| 11 | 控制台报 CORS 跨域错误 | 绕过了代理，直接请求了后端地址 | 业务代码统一使用 `/api` 相对路径 |
| 12 | 发布商品提示“请选择二级类别” | 商品必须挂在二级类别（小类）下 | 先到类别管理创建一级+二级类别 |
| 13 | 发布商品后直接变成“售罄下架” | 发布时库存填了 0 | 调整库存到大于 0 会自动恢复在售 |
| 14 | 图片上传被拒 | 商品图仅支持 JPG/PNG，单张 ≤5MB | 转换格式或压缩后重试 |
| 15 | 卖家登录后台后菜单点击无反应或跳回首页 | 旧版代码缺陷 | 确认使用最新 `main` 分支（菜单按路由名跳转） |
| 16 | 后端启动出现 JDK 26 WARNING | Spring Boot 2.7 与新版 JDK 的兼容提示 | 不影响运行，可忽略 |

## 11. 附录 B：常用命令速查

```bash
# ---------- 获取源码 ----------
git clone https://github.com/tyq-arch/single-merchant-shop-9.git
cd single-merchant-shop-9

# ---------- 安装前端依赖 ----------
cd frontend && npm install

# ---------- 编译后端 ----------
cd backend-java && mvn -DskipTests package

# ---------- 启动后端（终端 1）----------
cd backend-java
java -jar target/shop-backend-1.0.0.jar
# 或：mvn spring-boot:run

# ---------- 启动前端开发服务器（终端 2）----------
cd frontend && npm run dev
# 访问终端输出的 http://localhost:<端口>/

# ---------- 生产构建 ----------
cd frontend
rm -rf dist          # 重要：先清理旧产物
npm run build

# ---------- 预览构建产物 ----------
npm run preview
# 访问 http://localhost:4173/

# ---------- 环境版本核对 ----------
node -v && npm -v && java -version && mvn -v
```
