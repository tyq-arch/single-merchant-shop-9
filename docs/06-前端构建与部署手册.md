# 前端构建与部署手册

> 适用范围：在线购物系统（单卖家版）前端 —— 买家端 H5 + 卖家后台
> 技术栈：Vue 3 + Vite + Vue Router + Pinia + Element Plus
> 目标读者：需要从零拉取源码、本地运行或部署本系统的人员

---

## 1. 环境要求

### 1.1 软件版本

| 软件 | 最低要求 | 本项目实测版本 | 说明 |
|---|---|---|---|
| **Node.js** | `^20.19.0` 或 `>=22.12.0` | **v24.10.0** | 由 Vite 8 的 `engines` 字段决定，低于此版本 npm 会报错 |
| **npm** | 随 Node.js 安装 | **11.6.1** | 使用 npm 安装依赖 |
| **Python** | 3.10+ | **3.12.4** | 仅运行后端时需要，前端构建不依赖 |
| **Git** | 任意较新版本 | — | 获取源码使用 |
| **浏览器** | Chrome / Edge 最新版 | — | 需支持 ES2020 |

> ⚠️ **Node.js 版本是硬性条件。** Vite 8.3.3 的 `package.json` 中声明为
> `"engines": { "node": "^20.19.0 || >=22.12.0" }`，版本不足会导致安装或启动直接失败。

### 1.2 环境核对

在终端执行以下命令确认版本：

```bash
node -v     # 应输出 v20.19.0 以上，或 v22.12.0 以上
npm -v
python -V   # 仅在需要运行后端时检查
git --version
```

### 1.3 网络与磁盘

- 首次 `npm install` 会安装 **7 个直接依赖、约 120 个传递依赖**，需可访问 npm registry。
- 国内网络较慢时可切换镜像（可选）：

```bash
npm config set registry https://registry.npmmirror.com
```

- `node_modules` 约 200 MB，请预留磁盘空间。

## 4. 启动开发环境

### 4.1 启动顺序

**必须先启动后端，再启动前端。** 前端的开发代理指向 `127.0.0.1:8000`，后端未启动时页面能打开但所有接口都会失败。

```
终端 1：启动后端 (:8000)
        ↓
终端 2：启动前端 (:5173)
```

### 4.2 启动后端

```bash
cd backend
python run.py
```

等价于：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动成功的标志：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

验证：

- 服务信息：<http://127.0.0.1:8000/>
- **接口文档（Swagger UI）：<http://127.0.0.1:8000/docs>**
- OpenAPI 描述：<http://127.0.0.1:8000/openapi.json>

> ⚠️ `/docs` 只能通过 **8000 端口**访问。前端开发服务器（5173）只代理 `/api` 和 `/uploads`，
> 访问 `localhost:5173/docs` 会命中前端路由的兜底规则而被重定向到买家首页。

### 4.3 启动前端

```bash
cd frontend
npm run dev
```

启动成功的标志：

```
VITE v8.3.3  ready in 3440 ms
➜  Local:   http://localhost:5173/
```

**访问地址：<http://localhost:5173/>**

> ⚠️ **必须使用 `localhost`，不要使用 `127.0.0.1`。**
> 本项目实测 Vite 8 开发服务器监听在 IPv6 地址 `[::1]:5173`，
> 访问 `http://127.0.0.1:5173` 会连接失败。
> 需要让局域网其他设备访问时，追加 `--host` 参数（`npm run dev -- --host`）。

### 4.4 端口冲突处理

若 5173 已被占用，Vite 会自动尝试下一个可用端口，以终端实际输出为准。也可显式指定：

```bash
npm run dev -- --port 5174
```

后端端口被占用时：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

此时需同步修改 `frontend/vite.config.js` 中 `server.proxy` 的 `target`。

### 4.5 开发代理说明

[`frontend/vite.config.js`](../frontend/vite.config.js) 中配置了两条代理：

```js
server: {
  port: 5173,
  proxy: {
    '/api':     { target: 'http://127.0.0.1:8000', changeOrigin: true },
    '/uploads': { target: 'http://127.0.0.1:8000', changeOrigin: true },
  },
}
```

**作用**：浏览器请求的是同源的 `localhost:5173/api/...`，由 Vite 在背后转发到后端，
从而绕开浏览器的同源策略限制。

因此**业务代码中一律使用 `/api` 开头的相对路径**（见 `src/api/http.js` 的 `baseURL: '/api'`），
不写完整域名——这样开发环境与生产环境的业务代码零差异。

### 4.6 启动验证清单

| 检查项 | 验证方式 | 预期结果 |
|---|---|---|
| 后端存活 | 浏览器打开 `http://127.0.0.1:8000/docs` | 显示 Swagger 页面 |
| 前端存活 | 浏览器打开 `http://localhost:5173/` | 显示买家端首页 |
| **代理链路** | `curl http://localhost:5173/api/products/current` | 返回 JSON，而非 HTML |
| 卖家登录 | 打开 `/seller`，账号 `seller` / `seller123` | 进入工作台 |

## 5. 生产构建

### 5.1 构建前：清理旧产物（重要）

**本项目实测：`npm run build` 不会清空 `dist/` 中上一次构建的产物**，
多次构建后旧哈希文件会持续累积，导致目录越来越大，且容易误部署过期文件。

因此**每次构建前先删除 `dist/`**：

```bash
cd frontend

# Windows (Git Bash) / macOS / Linux
rm -rf dist

# Windows CMD 可用
rmdir /s /q dist
```

### 5.2 执行构建

```bash
npm run build
```

构建成功的标志（最后一行）：

```
✓ built in 7.87s
```

### 5.3 产物位置与结构

```
frontend/dist/
├── index.html          唯一入口 HTML
└── assets/             打包后的 JS / CSS / 字体等静态资源
    ├── index-<hash>.js         主包
    ├── IntentFormView-<hash>.js 各页面按路由懒加载切分
    ├── ...
    └── index-<hash>.css
```

文件名带内容哈希，内容不变则文件名不变，可安全地配置长期缓存。

### 5.4 关于构建体积警告

构建过程中可能出现：

```
(!) Some chunks are larger than 500 kB after minification.
```

这是 **Vite 对单个 chunk 超过 500 KB 的提示，不是构建失败**。
本项目主包约 866 KB（gzip 后约 276 KB），原因是 **Element Plus 采用全量引入**
（见 `src/main.js` 中的 `app.use(ElementPlus)`）。

后续优化方向：改为 Element Plus 按需引入，可显著降低主包体积。

## 7. 部署

### 7.1 上传静态文件

将 `dist/` 目录下的**全部内容**上传到静态服务器（Nginx / Apache / 对象存储均可）的站点根目录。

构建产物是纯静态文件，**不需要 Node.js 运行环境**。

### 7.2 Nginx 配置示例

```nginx
server {
    listen       80;
    server_name  your-domain.com;

    # 站点根目录指向 dist 上传后的位置
    root  /var/www/single-merchant-shop;
    index index.html;

    # 【必须】history 路由兜底
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 【必须】接口反向代理
    location /api/ {
        proxy_pass         http://127.0.0.1:8000;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
    }

    # 【必须】上传图片访问
    location /uploads/ {
        proxy_pass http://127.0.0.1:8000;
    }

    # 带哈希的静态资源可长期缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### 7.3 为什么必须配置 `try_files`

前端路由使用 **history 模式**（`src/router/index.js` 中的 `createWebHistory()`），
URL 中没有 `#`，例如 `/seller/publish`。

但服务器上**并不存在**名为 `/seller/publish` 的文件。若不做兜底：

- 用户从首页点击跳转 → 正常（由前端路由处理，不发请求）
- 用户**直接访问或刷新** `/seller/publish` → 服务器返回 **404**

`try_files $uri $uri/ /index.html;` 的作用是：找不到对应文件时统一返回 `index.html`，
交给前端路由解析。

> 这也是开发环境感知不到该问题的原因——Vite 开发服务器与 `vite preview` 已内置此兜底逻辑。

### 7.4 后端部署

生产环境启动后端时**不要使用 `--reload`**：

```bash
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2
```

- `--host 0.0.0.0`：允许外部访问（开发时用 `127.0.0.1` 仅本机可访问）
- `--workers`：工作进程数，按 CPU 核数调整

## 8. 常见问题排查

| # | 现象 | 原因 | 处理方法 |
|---|---|---|---|
| 1 | `npm install` 报 engine 版本不满足 | Node.js 版本过低 | 升级到 `20.19+` 或 `22.12+` |
| 2 | `127.0.0.1:5173` 打不开，`localhost:5173` 正常 | Vite 监听在 IPv6 `::1` | 统一使用 `localhost` |
| 3 | 页面能打开，但所有接口失败 | 后端未启动 | 先执行 `cd backend && python run.py` |
| 4 | 接口返回 HTML 而非 JSON | 请求走了前端路由兜底，未命中代理 | 检查路径是否以 `/api` 开头 |
| 5 | 端口被占用启动失败 | 已有进程占用 | 换端口，或结束占用进程 |
| 6 | `localhost:5173/docs` 打不开 | 代理只覆盖 `/api`、`/uploads` | 文档请访问 `127.0.0.1:8000/docs` |
| 7 | **部署后刷新子路径 404** | 缺少 history 路由兜底 | Nginx 配置 `try_files ... /index.html` |
| 8 | 部署后商品图片不显示 | `/uploads` 未反向代理 | 增加 `location /uploads/` 转发 |
| 9 | `dist/` 越来越大、存在多个 `index-*.js` | 旧产物未被清空 | **构建前先 `rm -rf dist`** |
| 10 | 控制台报 CORS 跨域错误 | 绕过了代理，直接请求了后端地址 | 业务代码统一使用 `/api` 相对路径 |
| 11 | 卖家后台菜单点击无反应或跳回首页 | 见下节说明 | 确认使用最新代码 |
| 12 | 手机号提示"请输入 11 位手机号" | 正常校验行为 | 按中国大陆手机号规则输入 11 位数字 |

### 关于第 11 项

卖家后台侧边菜单必须**按路由名跳转**，而非依赖 Element Plus 菜单的 `router` 模式。
若菜单点击后跳回买家首页，说明代码回退到了修复前的版本
（详见 `src/layouts/SellerLayout.vue` 中 `onSelect` 的注释）。请拉取最新 `main` 分支。

## 9. 附录 A：构建产物实测数据

以下为 Node v24.10.0 环境下的实测值，供评估加载性能参考：

| 项目 | 数值 |
|---|---|
| 构建耗时 | 约 8 秒 |
| 产物文件数 | 51 个（清理旧产物后） |
| 主包 `index-*.js` | 约 **866 KB**（gzip 约 **276 KB**） |
| 主样式 `index-*.css` | 约 **353 KB**（gzip 约 **47 KB**） |
| 页面级 chunk | 约 2–10 KB / 个（按路由懒加载） |
| 产物总大小 | 约 **1.6 MB** |

**懒加载说明**：`src/router/index.js` 中所有页面组件均使用 `() => import()` 动态导入，
因此每个页面被切分为独立 chunk，**仅在访问对应路由时才下载**，避免首屏加载全部页面代码。
