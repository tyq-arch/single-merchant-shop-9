# 页面原型设计文档

**项目：** 在线购物系统（单卖家版）
**角色：** 成员3 —— 前端开发岗
**版本：** V1.0
**日期：** 2026-10-07
**依据：** `需求分析.md`、`docs/03-接口设计文档.md`、`docs/04-前端技术栈调研报告.md`

---

## 1. 设计目标与原则

| 原则 | 说明 |
|---|---|
| 文案以后端为准 | 商品三态提示、状态标签、交易结果标签一律取后端 `message` / `status_label` / `result_label`，前端不自造中文 |
| 状态驱动渲染 | 买家端按 `state`（`NONE` / `ON_SALE` / `FROZEN`）分支渲染，卖家后台按商品 `status` 分支渲染 |
| 买家端零门槛 | 无需注册登录，首屏即商品页；所有操作路径不超过 2 次点击 |
| 口令码强提示 | 提交成功页必须显著展示口令码并提示「丢失无法找回」 |
| 后台无退出登录 | 需求 FR-034 明确约束，**任何后台页面都不出现退出登录入口** |
| 后台无商品编辑 | 需求 FR-002 明确约束，**不设计商品编辑页与编辑按钮** |

## 2. 页面清单与路由表

| 编号 | 页面 | 路由 | 布局 | 鉴权 | 对接接口 |
|---|---|---|---|---|---|
| B1 | 商品页 | `/` | BuyerLayout | 否 | `GET /api/products/current` |
| B2 | 提交购买意向 | `/buy` | BuyerLayout | 否 | `POST /api/buyer/intents` |
| B3 | 提交成功（口令码） | `/success` | BuyerLayout | 否 | —（数据由 B2 传入） |
| B4 | 口令码查询 | `/query` | BuyerLayout | 否 | `GET /api/buyer/intents/{code}` |
| B5 | 意向详情与管理 | `/intent` | BuyerLayout | 否 | `GET/PATCH /api/buyer/intents`、`POST /api/buyer/intents/cancel` |
| S1 | 卖家登录 | `/seller/login` | 独立 | 否 | `POST /api/seller/login` |
| S2 | 工作台（当前商品） | `/seller` | SellerLayout | 是 | `GET /api/seller/product/current`、`GET /api/seller/products/{id}/intents?status=IN_TRANSACTION`、冻结/解冻/下架/进入交易/标记交易/作废/重排 |
| S3 | 发布商品 | `/seller/publish` | SellerLayout | 是 | `POST /api/files/images`、`POST /api/seller/products` |
| S4 | 意向购买人 | `/seller/intents` | SellerLayout | 是 | `GET /api/seller/products/{id}/intents`、`GET .../intents/export` |
| S5 | 历史商品列表 | `/seller/history` | SellerLayout | 是 | `GET /api/seller/history` |
| S6 | 历史商品详情 | `/seller/history/:id` | SellerLayout | 是 | `GET /api/seller/history/{id}` |
| S7 | 修改密码 | `/seller/password` | SellerLayout | 是 | `POST /api/seller/password` |
| S8 | 操作日志 | `/seller/logs` | SellerLayout | 是 | `GET /api/seller/logs` |

> **口令码不进 URL。** B3 与 B5 的路径不含口令码，口令码经 Pinia + `sessionStorage` 传递，避免残留在浏览器历史记录中（详见技术栈报告 3.4 节）。

**卖家后台导航结构**（侧边栏固定 5 项，按需求 3.9 节「后台功能入口」）：

```
工作台 · 发布商品 · 意向购买人 · 历史商品 · 修改密码 · 操作日志
```

> 导航中**不含**「编辑商品」「退出登录」「注册」—— 三者均被需求明确排除。

## 3. 全局视觉与文案规范

### 3.1 状态徽标

| 状态来源 | 取值 | 徽标文案 | 配色 |
|---|---|---|---|
| 商品 `status` | `ON_SALE` | 在售 | 绿 `#16A34A` |
| | `FROZEN` | 已冻结 | 橙 `#EA580C` |
| | `OFF_SHELF` | 已下架 | 灰 `#64748B` |
| 意向 `status` | `QUEUED` | 排队中 | 蓝 `#2563EB` |
| | `IN_TRANSACTION` | 已进入交易 | 橙 `#EA580C` |
| | `SUCCESS` | 交易成功 | 绿 `#16A34A` |
| | `FAILED` | 交易失败 | 红 `#DC2626` |
| | `CANCELLED` | 已撤销 | 灰 `#64748B` |
| | `VOIDED` | 已作废 | 灰 `#64748B` |
| | `REQUEUED` | 重新排队中 | 蓝 `#2563EB` |

> 徽标文案直接绑定后端 `status_label` 字段，上表配色为前端按 `status` 枚举附加的样式类。

### 3.2 设计变量

| 变量 | 值 |
|---|---|
| 主色 | `#2563EB` |
| 危险色 | `#DC2626` |
| 买家端正文 | `16px` / 行高 `1.6` |
| 买家端最大宽度 | `640px` 居中 |
| 触控目标最小高度 | `44px` |
| 圆角 | 卡片 `12px`，按钮 `8px` |
| 间距基数 | `4px`（使用 4 的倍数） |

### 3.3 通用提示与错误处理

| 场景 | 提示方式 | 文案来源 |
|---|---|---|
| 表单字段不合法 | 字段下方红字 | 前端规则（见技术栈报告 3.8 节） |
| 后端 422 | 顶部消息条 | 取 `error.message` |
| 后端 409（状态冲突） | 顶部消息条 + 刷新当前数据 | 取 `error.message` |
| 后端 410（口令码失效） | 全屏失效提示页 | 取 `error.message` |
| 后端 401 | 清除令牌 → 跳转 `/seller/login` | 固定文案「登录已过期，请重新登录」 |
| 网络不可达 | 顶部消息条 | 固定文案「无法连接服务器，请确认后端已启动」 |
| 危险操作（下架、撤销、作废） | 二次确认对话框 | 各自固定文案 |

## 4. 买家端页面原型

### B1 商品页 `/`

**职责：** 匿名浏览商品，按三态渲染（FR-043~FR-046）。

#### B1-a 无商品在售（`state = NONE`）

```
┌───────────────────────────────────┐
│  单卖家小店              [查询意向] │
├───────────────────────────────────┤
│                                   │
│                                   │
│              ┌─────┐              │
│              │ 📦  │              │
│              └─────┘              │
│                                   │
│          暂无商品在售               │  ← 直接取 message 字段
│                                   │
│                                   │
└───────────────────────────────────┘
```

- 元素：顶部栏（店名 + 「查询意向」入口）、空状态图标、空状态文案
- 不展示任何商品信息，无购买入口（FR-044）
- 文案取自响应体 `message`，前端不硬编码

#### B1-b 在售（`state = ON_SALE`）

```
┌───────────────────────────────────┐
│  单卖家小店              [查询意向] │
├───────────────────────────────────┤
│  ┌─────────────────────────────┐  │
│  │                             │  │
│  │         商品主图             │  │  ← 宽高比 4:3
│  │      object-fit: cover      │  │     image_url 为空时显示占位图
│  │                             │  │
│  └─────────────────────────────┘  │
│                                   │
│  手工陶瓷杯                        │  ← name，超出 2 行省略
│  ¥ 99.90                          │  ← price，保留 2 位小数
│  ───────────────────────────────  │
│  手作限量                          │  ← description，可换行
│                                   │
│  ┌─────────────────────────────┐  │
│  │         我 要 购 买          │  │  ← 吸底固定，点击 → /buy
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

#### B1-c 已冻结（`state = FROZEN`）

与 B1-b 结构相同，仅底部按钮变化：

```
│  ┌─────────────────────────────┐  │
│  │       商品交易中（不可点击）   │  │  ← 禁用态，灰色
│  └─────────────────────────────┘  │
```

- 商品信息仍完整可见（需求 3.8 节：冻结期间买家看到什么）
- 按钮为 `disabled`，无提交入口（FR-012 / FR-046）
- 顶部额外显示提示条，文案取 `message`（即「商品交易中」）

**交互：** 页面加载即请求 `GET /api/products/current`；「查询意向」跳转 `/query`。

### B2 提交购买意向 `/buy`

**职责：** 填写姓名与联系电话，提交后获得口令码（FR-013 / FR-047）。

```
┌───────────────────────────────────┐
│  ← 返回            填写购买信息     │
├───────────────────────────────────┤
│  ┌─────────────────────────────┐  │
│  │ [图] 手工陶瓷杯              │  │  ← 商品摘要卡片，防止填错商品
│  │      ¥ 99.90                │  │
│  └─────────────────────────────┘  │
│                                   │
│  姓名 *                           │
│  ┌─────────────────────────────┐  │
│  │ 请输入您的姓名               │  │
│  └─────────────────────────────┘  │
│                                   │
│  联系电话 *                        │
│  ┌─────────────────────────────┐  │
│  │ 请输入联系电话               │  │
│  └─────────────────────────────┘  │
│                                   │
│  ℹ️ 姓名和电话仅用于本次线下交易，   │
│     交易结束后将脱敏处理            │  ← NFR-003 隐私告知
│                                   │
│  ┌─────────────────────────────┐  │
│  │         提 交 意 向          │  │  ← 提交中禁用防重复点击
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

| 交互 | 说明 |
|---|---|
| 商品摘要 | 从路由进入时携带商品信息；若直接访问且无数据，回退请求 `GET /api/products/current` |
| 前端校验 | 姓名去空格非空且 ≤64 字；电话 5–20 位，仅数字/`+`/`-`/空格 |
| 提交 | `POST /api/buyer/intents`，体含 `product_id`、`buyer_name`、`buyer_phone` |
| 提交中 | 按钮置 `loading` 并禁用，防止重复提交产生多条意向 |
| 成功 | 口令码等数据存入 `useBuyerStore`，跳转 `/success` |
| 失败 409 | 商品已被他人抢先进入交易或已被下架 → 提示并跳回 `/` 刷新 |
| 失败 422 | 展示 `error.message`（如「联系电话格式不正确」） |

### B3 提交成功 / 口令码展示 `/success`

**职责：** 当场展示口令码并强提示保存（FR-048 / FR-050）。**本页是本项目最关键的一页。**

```
┌───────────────────────────────────┐
│              提交成功               │
├───────────────────────────────────┤
│              ┌─────┐              │
│              │  ✅  │              │
│              └─────┘              │
│                                   │
│        您的排队序号：第 1 位         │  ← queue_position
│                                   │
│  ┌─────────────────────────────┐  │
│  │      您的口令码              │  │
│  │                             │  │
│  │      K 7 M 2 P Q 9 X T R    │  │  ← 大字、字间距加宽、等宽字体
│  │                             │  │     点击整块即可复制
│  │        [ 复 制 口 令 码 ]     │  │
│  └─────────────────────────────┘  │
│                                   │
│  ⚠️ 请务必自行保存口令码           │
│     这是查询、修改、撤销该意向的      │
│     唯一凭证，丢失无法找回。        │  ← 取 notice 字段原文
│                                   │
│  ┌─────────────────────────────┐  │
│  │      查看我的排队状态         │  │  → /intent
│  └─────────────────────────────┘  │
│  ┌─────────────────────────────┐  │
│  │         返回首页             │  │  → /
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

| 交互 | 说明 |
|---|---|
| 提示原文 | 直接渲染后端 `notice` 字段，不自造文案 |
| 复制 | `navigator.clipboard.writeText()`，成功后按钮变「已复制 ✓」并 2 秒后还原；失败时降级为 `document.execCommand('copy')` |
| 数据来源 | 由 B2 写入 `useBuyerStore`；若 store 为空（如刷新后丢失），显示兜底提示并引导至 `/query` |
| 离开提醒 | 用户点击返回/跳转时，`beforeunload` 或路由守卫弹出「确认已保存口令码？」二次确认 |

### B4 口令码查询 `/query`

**职责：** 买家凭口令码认领自己的意向（FR-022 / AC-008）。

```
┌───────────────────────────────────┐
│  ← 返回            查询我的意向     │
├───────────────────────────────────┤
│                                   │
│  请输入您的口令码                   │
│  ┌─────────────────────────────┐  │
│  │ K7M2PQ9XTR                  │  │  ← 自动转大写、去空格
│  └─────────────────────────────┘  │
│                                   │
│  ┌─────────────────────────────┐  │
│  │           查 询              │  │
│  └─────────────────────────────┘  │
│                                   │
│  ℹ️ 口令码是您查询、修改、撤销该笔    │
│     意向的唯一凭证，丢失无法找回。   │
│     请检查是否与提交成功页一致。     │
│                                   │
└───────────────────────────────────┘
```

| 交互 | 说明 |
|---|---|
| 输入处理 | 自动 `trim` + 转大写（后端生成的口令码为去混淆大写字符集） |
| 查询成功 | 口令码写入 `useBuyerStore`，跳转 `/intent` |
| 410 失效 | 原地红字提示，文案取 `error.message`，并说明可能原因（交易已结束 / 商品已下架 / 已撤销） |
| 空输入 | 前端拦截，提示「请输入口令码」 |

│                                   │
└───────────────────────────────────┘
```

- 「修改我的信息」「撤销排队意向」两个按钮**隐藏**（依据 `can_edit` / `can_cancel`）

#### B5-c 已终结（`status ∈ {SUCCESS, FAILED, VOIDED, CANCELLED}`）

```
├───────────────────────────────────┤
│        交易成功 / 交易失败 /         │
│        已作废 / 已撤销              │  ← status_label
│                                   │
│  本意向已结束，口令码已失效。        │
│  不能再查询、修改或撤销。           │
│                                   │
│  ┌─────────────────────────────┐  │
│  │         返回首页             │  │
│  └─────────────────────────────┘  │
└───────────────────────────────────┘
```

| 交互 | 说明 |
|---|---|
| 数据加载 | 从 `useBuyerStore` 取口令码 → `GET /api/buyer/intents/{code}` |
| 排队位置 | 渲染 `position` 字段（初始加载与状态刷新后均以此为准） |
| 修改信息 | 内联表单，仅提交实际改动的字段；后端要求姓名与电话至少一项，**位次不变**（FR-023） |
| 撤销 | 二次确认「撤销后将从队列移除，且无法恢复，确认撤销？」→ `POST /api/buyer/intents/cancel` |
| 撤销成功 | 展示 B5-c 已撤销态 |
| 刷新状态 | 提供「刷新」按钮重新拉取，应对卖家侧状态变化 |
| 口令码失效（410） | 全屏提示页，说明口令码已失效及可能原因 |

### S2 工作台 `/seller`

**职责：** 后台主页面，按当前商品状态分支渲染，并承载全部交易操作。

#### S2-a 无商品（`product = null`）

```
┌────────────┬──────────────────────────────────────────────┐
│ 单卖家小店  │  工作台                                       │
│            ├──────────────────────────────────────────────┤
│ ▸ 工作台    │                                              │

> **关键设计点：交易进行中时不显示「手动解冻」。** 后端 `unfreeze` 在存在进行中交易时返回 409（见接口文档 5.7）。前端依据「是否存在 `IN_TRANSACTION` 订单」这一条件决定显示「标记交易成功/失败」还是「手动解冻」，避免用户触发必然失败的操作。

#### S2-d 冻结但无进行中交易（手动冻结）

显示商品卡片 + 「手动解冻」按钮（`POST .../unfreeze`），并提示「解冻后恢复在售、重新接收意向，不直接进入交易」（FR-010）。

#### S2-e 交易失败后的失败者处理

当存在 `status = FAILED` 的订单时，在订单卡片区域增加处理区：

```
│  ┌──────────────────────────────────────────┐│
│  │  🔴 张三 交易失败                          ││
│  │                                          ││
│  │  ┌──────────────┐ ┌──────────────┐      ││
│  │  │   作 废       │ │  重新排队     │      ││
│  │  └──────────────┘ └──────────────┘      ││
│  │  重新排队仅可操作 1 次                     ││
│  └──────────────────────────────────────────┘│
```

| 按钮 | 接口 | 二次确认文案 |
|---|---|---|
| 作废 | `POST /api/seller/orders/{id}/void` | 「作废后该买家意向终结，仅影响该买家本人」 |
| 重新排队 | `POST /api/seller/orders/{id}/requeue` | 「将放回队尾并**生成新口令码**，原口令码已失效；仅可重排 1 次」 |

> 重新排队成功后需展示新口令码供卖家转告买家（接口返回 `command_code`）。

#### S2-f 数据加载逻辑

工作台需两个请求才能完整渲染：

1. `GET /api/seller/product/current` → 商品与状态
2. 若有商品：`GET /api/seller/products/{id}/intents?page=1&page_size=100` → 队列概览
3. 从队列结果中筛出 `status === 'IN_TRANSACTION'` 的订单 → 决定 S2-c / S2-d 分支
4. 筛出 `status === 'FAILED'` 的订单 → 决定 S2-e 处理区

> 说明：后端未提供「查询当前进行中订单」的独立接口，前端通过一次队列列表请求在客户端筛选。数据量级为单商品队列（个位数），无性能问题。

## 6. 关键交互流程

### 6.1 买家完整成交路径

```
B1 商品页(在售) → 点击「我要购买」
   → B2 填写姓名/电话 → 提交
   → POST /api/buyer/intents
   → B3 展示口令码 + 强提示保存
   → 点击「查看我的排队状态」→ B5 排在 2 位 [排队中]
   → （卖家进入交易）
   → B5 刷新 → [已进入交易]，不可改、不可撤
   → （卖家标记成功）
   → B5 刷新 → 410 → 展示「口令码已失效」
```

### 6.2 卖家失败后自动递补路径

```
S2-b 在售，队列 A(1) B(2)
   → 点击「与队首进入交易」→ 二次确认
   → POST .../start-transaction → 工作台刷新为 S2-c
   → 点击「标记交易失败」→ 填备注 → 确认
   → POST /api/seller/orders/A/transaction {result: FAILED}
   → 响应提示 B 已自动递补
   → 工作台刷新：出现 A 的 FAILED 处理区（S2-e）
                + B 的进行中订单卡片（S2-c）
   → 点击 A 的「作废」（或「重新排队」→ 展示新口令码）
   → 继续对 B 标记交易成功 → 商品下架，进入历史
```
