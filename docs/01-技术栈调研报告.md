## 1. 调研目标与范围

本报告为后端选型提供依据，覆盖后端语言/框架、数据库、鉴权与口令码方案、接口文档与测试方案。
选型需满足需求文档中的关键约束：

| 需求编号 | 约束要点 | 对选型的影响 |
|---|---|---|
| NFR-013 | 商品冻结、排队、递补需保证顺序一致性，防止超卖 | 需要强事务与可靠的写串行机制 |
| NFR-014 | 队列严格按提交时间先到先得 | 需要可控的写入顺序，避免并发乱序 |
| NFR-015 / FR-031 | 同一商品多次交易记录必须完整保留 | 数据库需支持独立的历史/交易记录表 |
| NFR-004 / NFR-005 | 口令码随机、唯一、不可枚举、可即时失效 | 需要安全随机源与状态字段 |
| NFR-002 / NFR-006 | 密码哈希存储，防 SQL 注入 / XSS / CSRF | 需要成熟框架的内置防护与参数化查询 |
| NFR-007 | 可用性 ≥ 99% | 部署越简单越稳定 |
| NFR-009 | 模块化、接口文档、日志规范 | 框架最好能自动生成接口文档 |
| 交付节奏 | 课程项目、Scrum 迭代、需快速可演示 | 开发效率优先 |

## 2. 后端技术方案对比

| 维度 | Python + FastAPI（采用） | Python + Flask | Java + Spring Boot | Node.js + Express |
|---|---|---|---|---|
| 开发效率 | 高，声明式路由 + 类型校验 | 高，但校验/文档需自行拼装 | 中，配置样板多 | 高 |
| 请求校验 | Pydantic 内建，中文错误可控 | 需额外引入 marshmallow 等 | Bean Validation，较重 | 需 joi/zod 自行接入 |
| 接口文档 | 内建 OpenAPI/Swagger（`/docs`） | 需 flask-smorest 等扩展 | springdoc 扩展 | 需 swagger-jsdoc |
| 性能 | 高（Starlette + uvicorn） | 中 | 高（JVM） | 高（单线程事件循环） |
| 并发模型 | 同步端点自动跑线程池，天然适配 SQLite | 需 gunicorn 多 worker | 线程池成熟 | 事件循环，阻塞驱动易踩坑 |
| 依赖/部署复杂度 | 低，pip 一条命令 | 低 | 高（Maven + JDK + 配置） | 中（Node 运行时） |
| 本机环境适配 | **Python 3.14 + pip 已就绪；无 Maven/Node** | 已就绪 | 缺 Maven，需额外安装 | 未安装 Node |
| 团队学习成本 | 低 | 低 | 高 | 中 |
| 结论 | **采用** | 备选 | 不采用 | 不采用 |

**决策理由：**

1. 本机已具备 Python 3.14 与 pip，FastAPI 可零门槛安装运行，满足"后端环境搭建"快速落地；
2. 内建 OpenAPI 文档，直接满足 NFR-009"接口文档"要求，减少手工维护成本；
3. Pydantic 能在入口统一完成参数校验（姓名、电话、价格等），符合"仅在系统边界校验"的原则；
4. 同步端点由 FastAPI 自动放入线程池执行，与 SQLite 的同步驱动天然匹配，避免异步阻塞陷阱。

## 3. 数据库方案对比

| 维度 | SQLite（采用） | MySQL | PostgreSQL |
|---|---|---|---|
| 部署 | 零配置，单文件，随项目提交即可运行 | 需安装并启动服务端 | 需安装并启动服务端 |
| 事务 | 完整 ACID，支持 `BEGIN IMMEDIATE` 写锁 | 完整 ACID | 完整 ACID |
| 并发写 | 单写者模型，配合写串行天然满足 FIFO | 高并发多写 | 高并发多写 |
| 本项目数据量级 | 单卖家、单商品、个位数队列 —— 完全够用 | 过剩 | 过剩 |
| 备份/恢复（NFR-011） | 复制 `.db` 文件，或 `VACUUM INTO` | mysqldump | pg_dump |
| 演示与提交 | 开箱即用，评审可直接运行 | 需附环境说明 | 需附环境说明 |
| 结论 | **采用** | 不采用 | 不采用 |

**决策理由：** 系统为单卖家模式，并发规模极小（同一时间仅一件商品、队列个位数），SQLite 的"单写者 + 写事务串行"反而与"先到先得、不可超卖"的业务诉求高度契合；且零配置、便于课程项目提交与现场演示。

> 迁移预案：数据访问集中在 `database.py` 与服务层，若后续需要 MySQL，可在不改业务逻辑的前提下替换数据访问实现。

## 4. 关键子方案

| 主题 | 方案 | 对应需求 |
|---|---|---|
| 密码存储 | PBKDF2-HMAC-SHA256，20 万次迭代 + 随机盐，`hmac.compare_digest` 恒定时比较 | NFR-002 / NFR-006 |
| 卖家会话 | HMAC 签名的无状态令牌（含过期时间），后台无退出登录，令牌自然过期 | FR-032 / FR-034 |
| 口令码 | `secrets` 生成 10 位、去混淆字符集（无 0/O/1/I）的随机码；全局唯一性由主键 + 重试保证 | NFR-004 / FR-014 / FR-050 |
| 口令码失效 | `command_code.status` 状态位 + `expires_at`，交易成功/失败、商品下架、买家撤销时立即置为失效 | NFR-005 / FR-026 |
| 并发控制 | SQLite WAL 模式 + `BEGIN IMMEDIATE` + 进程内写锁，保证排队、冻结、递补串行 | NFR-013 / NFR-014 |
| 商品快照 | 下单瞬间把商品名称/描述/图片/价格固化到订单行，保证历史可追溯 | FR-007 / NFR-015 |
| 隐私脱敏 | 交易终结或商品下架后，列表与历史统一按 `前3位****后4位` 展示手机号 | FR-019 / NFR-003 |
| 接口文档 | FastAPI 自动生成 Swagger UI（`/docs`）与 ReDoc（`/redoc`） | NFR-009 |
| 自动化测试 | pytest + Starlette TestClient，28 条端到端用例覆盖主流程与边界 | NFR-009 / NFR-010 |

## 6. 环境要求与搭建步骤

**环境要求：** Python ≥ 3.10（本机 3.14）、pip；无需数据库服务端。

```bash
# 1) 安装依赖
cd backend
python -m pip install -r requirements.txt

# 2) 启动后端（首次启动自动建表并写入唯一卖家账号）
python -m uvicorn app.main:app --reload --port 8000
# 或： python run.py

# 3) 访问接口文档
# Swagger UI: http://127.0.0.1:8000/docs
# ReDoc:      http://127.0.0.1:8000/redoc

# 4) 运行自动化测试
python -m pytest tests -q
```

**默认卖家账号：** 用户名 `seller`，密码 `seller123`（可通过环境变量 `SHOP_SELLER_USERNAME` / `SHOP_SELLER_PASSWORD` 覆盖）。

**可配置项（环境变量）：** `SHOP_DB_PATH`、`SHOP_UPLOAD_DIR`、`SHOP_SECRET_KEY`、`SHOP_TOKEN_TTL_SECONDS`、`SHOP_COMMAND_CODE_TTL_DAYS`、`SHOP_MAX_IMAGE_BYTES`。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| SQLite 单写者，高并发写入排队 | 请求变慢 | 本系统并发极小；WAL 模式读写分离；必要时迁移 MySQL |
| 口令码被暴力枚举 | 隐私泄露 | 10 位去混淆字符集（约 2.8×10¹⁴ 组合）+ 唯一性校验 |
| 令牌无服务端吊销 | 令牌泄露后有效期内可用 | 缩短有效期；修改密码后可结合指纹重置（后续增强） |
| 缺少 Maven/JDK 生态 | 无法走 Java 方案 | 已选择 Python 方案规避 |

---

## 8. 结论

综合开发效率、本机环境、并发契合度与课程交付节奏，后端采用 **Python 3.14 + FastAPI + SQLite** 组合。
该组合零配置即可运行、自动产出接口文档、并以写事务串行天然满足"先到先得、不可超卖"的核心业务约束，是当前项目条件下的最优解。
