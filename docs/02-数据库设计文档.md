# 数据库设计文档

**项目：** 在线购物系统（单卖家版）
**角色：** 成员2 —— 后端开发岗
**版本：** V1.0
**日期：** 2026-10-05
**数据库：** SQLite 3.50
**DDL 文件：** [backend/app/schema.sql](../backend/app/schema.sql)

---

## 1. 设计目标与原则

| 原则 | 说明 | 对应需求 |
|---|---|---|
| 唯一在售 | 任一时刻最多一条商品处于"在售/冻结"，由应用层事务保证 | FR-008 / AC-025 |
| 先到先得 | 排队序号由写事务串行分配，严格按提交顺序 | FR-015 / NFR-014 |
| 历史完整 | 交易记录独立成表，多轮失败逐条保留，不覆盖 | FR-031 / NFR-015 / AC-031 |
| 快照可追溯 | 订单行固化商品快照，历史详情可还原 | FR-007 / FR-005 |
| 最小化收集 | 买家不建账号表，仅在本单存姓名电话，终结后脱敏 | NFR-003 / FR-019 |
| 口令码即凭证 | 口令码全局唯一，与订单一一对应，状态可即时失效 | FR-014 / NFR-004 / NFR-005 |

## 2. 逻辑模型

系统共 7 张表，与需求文档 6.1 实体关系图一一对应：

```
seller ──1:N──> operation_log
seller ──1:N──> product
product ──1:N──> order_intent ──1:1──> command_code
product ──1:N──> queue_item ──N:1──> order_intent
order_intent ──1:N──> transaction_record
product ──1:N──> transaction_record
```

| 表名 | 中文名 | 说明 |
|---|---|---|
| `seller` | 卖家 | 唯一固定账号，初始化写入，无注册 |
| `product` | 商品 | 名称/描述/图片/价格/状态，发布后不可编辑 |
| `order_intent` | 订单（购买意向） | 含商品快照、买家信息、意向状态、排队序号、口令码 |
| `command_code` | 口令码 | 全局唯一，与订单一一对应，可即时失效 |
| `queue_item` | 排队队列 | 商品 + 订单 + 序号 + 提交时间，严格 FIFO |
| `transaction_record` | 交易记录 | 每轮交易结果，多次失败逐条保留 |
| `operation_log` | 操作日志 | 卖家关键操作留痕 |

## 3. 表结构明细

### 3.1 seller（卖家）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键（UUID，去横线） |
| username | TEXT | NOT NULL, UNIQUE | 登录用户名，固定指定 |
| password_hash | TEXT | NOT NULL | PBKDF2-SHA256 哈希（`算法$迭代$盐$摘要`） |
| created_at | TEXT | NOT NULL | 创建时间 |

> 系统仅一条记录，由 `init_db.py` 在首次启动时写入，无注册入口（FR-033）。

### 3.2 product（商品）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键 |
| name | TEXT | NOT NULL | 商品名称（必填） |
| description | TEXT | 可空 | 商品描述（选填） |
| image_url | TEXT | 可空 | 主图地址（选填，最多一张） |
| price_cents | INTEGER | NOT NULL, >0 | 价格（单位：分，避免浮点误差） |
| status | TEXT | NOT NULL, IN(ON_SALE,FROZEN,OFF_SHELF) | 商品状态 |
| published_at | TEXT | NOT NULL | 发布时间（历史倒序依据） |
| updated_at | TEXT | NOT NULL | 最后变更时间 |

### 3.3 order_intent（订单 / 购买意向）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键 |
| product_id | TEXT | NOT NULL, FK→product.id | 所属商品 |
| snapshot_name | TEXT | NOT NULL | 商品快照-名称 |
| snapshot_description | TEXT | 可空 | 商品快照-描述 |
| snapshot_image_url | TEXT | 可空 | 商品快照-图片 |
| snapshot_price_cents | INTEGER | NOT NULL | 商品快照-价格（分） |
| buyer_name | TEXT | NOT NULL | 买家姓名（仅本次交易） |
| buyer_phone | TEXT | NOT NULL | 买家电话（仅本次交易，终结后脱敏展示） |
| status | TEXT | NOT NULL, IN(QUEUED,CANCELLED,IN_TRANSACTION,SUCCESS,FAILED,VOIDED,REQUEUED) | 意向状态 |
| queue_position | INTEGER | 可空 | 当前排队序号（撤销/终结后为 NULL） |
| requeue_count | INTEGER | NOT NULL, 默认 0 | 重新排队次数（上限 1） |
| command_code | TEXT | 可空 | 当前生效口令码（便于关联查询） |
| created_at | TEXT | NOT NULL | 提交时间 |
| updated_at | TEXT | NOT NULL | 最后变更时间 |

### 3.4 command_code（口令码）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| code | TEXT | PK | 口令码本体，全局唯一 |
| order_id | TEXT | NOT NULL, FK→order_intent.id | 关联订单 |
| product_id | TEXT | NOT NULL, FK→product.id | 关联商品（下架批量失效用） |
| status | TEXT | NOT NULL, IN(ACTIVE,INVALID) | 生效 / 失效 |
| created_at | TEXT | NOT NULL | 生成时间 |
| expires_at | TEXT | 可空 | 过期时间（安全兜底，默认 30 天） |

> 重新排队时（需求 TBD-03）为新队列项**重新生成**口令码，历史口令码保持失效，详见第 6 节。

### 3.5 queue_item（排队队列）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键 |
| product_id | TEXT | NOT NULL, FK→product.id | 所属商品 |
| order_id | TEXT | NOT NULL, FK→order_intent.id | 关联订单 |
| position | INTEGER | NOT NULL | 排队序号，1 最小（队首） |
| submitted_at | TEXT | NOT NULL | 入队时间 |

> 唯一约束 `UNIQUE(product_id, order_id)`：同一订单不能重复入队，保障"最多重新排队一次"实现可靠。

### 3.6 transaction_record（交易记录）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键 |
| order_id | TEXT | NOT NULL, FK→order_intent.id | 关联订单 |
| product_id | TEXT | NOT NULL, FK→product.id | 关联商品 |
| result | TEXT | NOT NULL, IN(SUCCESS,FAILED) | 交易结果 |
| note | TEXT | 可空 | 卖家备注 |
| created_at | TEXT | NOT NULL | 记录时间 |

> 每轮交易独立 INSERT，**不覆盖**；同一商品多次失败全部可追溯（AC-031）。

### 3.7 operation_log（操作日志）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | 主键 |
| seller_id | TEXT | FK→seller.id，可空 | 操作人 |
| action | TEXT | NOT NULL | 动作编码（如 PUBLISH_PRODUCT、TRANSACTION_SUCCESS） |
| detail | TEXT | 可空 | 可读描述 |
| created_at | TEXT | NOT NULL | 操作时间 |

## 5. 状态字典与流转

### 5.1 商品状态（product.status）

| 状态 | 含义 | 可流转到 |
|---|---|---|
| ON_SALE | 在售，可提交意向 | FROZEN、OFF_SHELF |
| FROZEN | 已冻结（手动或进入交易自动），不收新意向 | ON_SALE、OFF_SHELF |
| OFF_SHELF | 已下架（终态） | — |

### 5.2 意向状态（order_intent.status）

| 状态 | 含义 | 可流转到 |
|---|---|---|
| QUEUED | 排队中 | CANCELLED、IN_TRANSACTION、VOIDED |
| CANCELLED | 买家撤销（终态） | — |
| IN_TRANSACTION | 已进入交易 | SUCCESS、FAILED |
| SUCCESS | 交易成功（终态） | — |
| FAILED | 交易失败，待卖家处理 | VOIDED、REQUEUED |
| VOIDED | 已作废（终态） | — |
| REQUEUED | 重新排队中（放回队尾） | IN_TRANSACTION、CANCELLED、VOIDED |

### 5.3 口令码状态（command_code.status）

| 状态 | 含义 |
|---|---|
| ACTIVE | 生效：可查询、可修改（仅排队中）、可撤销（仅排队中） |
| INVALID | 失效：不可查、不可改、不可撤 |

## 6. 口令码生命周期设计

| 触发事件 | 处理 | 实现位置 |
|---|---|---|
| 提交购买意向 | 生成唯一口令码，置 ACTIVE | `services/codes.create_code_for_order` |
| 买家撤销意向 | 该订单口令码置 INVALID | `services/intent_service.cancel_by_code` |
| 交易成功 | 该商品**全部**口令码置 INVALID | `services/transaction_service.mark_transaction` |
| 交易失败 | 失败者口令码置 INVALID | `services/transaction_service.mark_transaction` |
| 商品下架 | 关联商品全部口令码置 INVALID | `services/product_service.off_shelf_product` |
| 过期兜底 | `expires_at` 到期即视为失效 | `services/codes.find_active_code` |

> **TBD-03 决策说明：** 需求文档指出"交易失败后口令码已失效，重新排队时是生成新口令码还是原码继续有效"尚未确认。本实现采用**重新排队时生成新口令码**，使买家在 `REQUEUED` 状态下仍可查询与撤销；该决策已在接口响应中明确返回新口令码，后续如需求变更，仅需调整 `requeue_order` 一处。

## 7. 并发与一致性设计（NFR-013 / NFR-014）

| 机制 | 说明 |
|---|---|
| WAL 模式 | `PRAGMA journal_mode = WAL`，读不阻塞写，提升并发读性能 |
| 写事务串行 | 所有写操作经 `database.transaction()`，内部持进程内可重入锁 + `BEGIN IMMEDIATE` |
| 序号原子分配 | 排队序号在写事务内以 `MAX(position)+1` 分配，杜绝并发抢位 |
| 递补原子化 | "失败→失效口令码→移除队首→下一位进入交易→冻结商品"在同一事务内完成 |
| 唯一在售校验 | 发布前在写事务内校验是否存在 ON_SALE/FROZEN 商品，防止并发重复发布 |

## 8. 隐私与脱敏（FR-019 / NFR-003）

- 买家不建账号表，姓名与电话仅存储于本单 `order_intent`；
- 在**卖家查看意向购买人**与**历史详情**接口中，当订单已终结或商品已下架时，手机号按 `前3位****后4位` 脱敏返回；
- 交易进行中（卖家需联系买家）返回完整号码；
- 脱敏在**输出层**完成，不破坏数据完整性，兼顾 AC-030（历史需展示电话）与 FR-019（需脱敏）。

## 9. 备份与恢复（NFR-011）

| 方式 | 命令 |
|---|---|
| 冷备份 | 直接复制 `backend/data/shop.db`（建议在服务停止时） |
| 热备份 | `sqlite3 shop.db "VACUUM INTO 'backup_20261005.db'"` |
| 恢复 | 用备份文件替换 `shop.db` 后重启服务 |

数据库文件默认位于 `backend/data/shop.db`，可通过 `SHOP_DB_PATH` 环境变量重定向。

## 10. 初始化与种子数据

`init_db.py` 在应用启动（FastAPI lifespan）时执行：

1. `ensure_dirs()` 创建数据目录与上传目录；
2. 执行 `schema.sql`（全部 `CREATE TABLE IF NOT EXISTS`，幂等）；
3. `seed_seller()` 在无卖家记录时写入唯一固定账号（用户名/密码来自配置）。
